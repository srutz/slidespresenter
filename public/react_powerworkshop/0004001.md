# 4.1 Styling mit Tailwind CSS / Tailwind CSS im Seminar-Stack

## Was ist Tailwind CSS?

- Tailwind CSS ist ein Utility-First CSS-Framework und im Seminar der Standard für das Styling
- Statt eigene CSS-Klassen zu schreiben, werden viele kleine, einzweckige Klassen im `className` kombiniert
- Beispiele: `p-4` (Padding), `text-lg` (Schriftgröße), `bg-blue-600` (Hintergrund), `rounded-lg` (Rundung)
- Tailwind erzeugt beim Build nur das CSS für Klassen, die im Quellcode tatsächlich vorkommen
- Version 4 wird CSS-first konfiguriert: kein `tailwind.config.js` und keine PostCSS-Konfiguration mehr nötig

```typescript
export function Hello() {
  return <h1 className="text-2xl font-bold text-blue-700">Hallo Tailwind</h1>
}
```

## Warum Utility-First?

- Keine Namensfindung: kein `.card-header-title-inner`, keine BEM-Konventionen
- Kein Wechsel zwischen Komponenten-Datei und CSS-Datei, Markup und Styling stehen zusammen
- Kein "toter" CSS-Code: Löscht man eine Komponente, verschwinden auch ihre Styles
- Globales CSS kann nicht versehentlich andere Komponenten beeinflussen
- Ein festes Design-System (Abstände, Farben, Schriftgrößen) sorgt für konsistente Oberflächen
- Das Build-Ergebnis bleibt klein, da nur genutzte Klassen enthalten sind

## Abgrenzung zu klassischem CSS

```css
/* Klassisches CSS */
.card {
  padding: 1rem;
  border-radius: 0.5rem;
  background: white;
}
```

```typescript
// Tailwind: dieselben Eigenschaften als Utility-Klassen
<div className="p-4 rounded-lg bg-white">...</div>
```

- Tailwind ersetzt CSS nicht, es erzeugt CSS: jede Klasse entspricht einer oder wenigen CSS-Deklarationen
- Lange Klassenlisten werden nicht kopiert, sondern in React-Komponenten gekapselt (siehe 4.8)
- Der Einwand "das ist wie Inline-Styles" stimmt nicht: Tailwind kennt Breakpoints, Hover-States, Dark Mode und Pseudo-Klassen
