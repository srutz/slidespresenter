# 8.5 useHooks als Standard-Hook-Sammlung / Vorhandenen Hook verwenden oder selbst entwickeln

## Entscheidungshilfe

- **Nutzen**, wenn der Hook ein Standardproblem löst, gut getestet ist und wir nichts Besonderes brauchen
- **Selbst schreiben**, wenn
    - der Hook nur wenige Zeilen hat und eine Abhängigkeit unverhältnismäßig wäre
    - wir fachliche Logik brauchen (Domänen-Hook, z. B. `useCart`)
    - die Bibliothek gealtert oder nicht typisiert ist
    - wir exakt kontrollieren müssen, wie sich der Hook verhält (Timing, Cleanup, SSR)
- **Kopieren statt installieren**: Der Code von useHooks ist kurz und lässt sich in `src/hooks/` übernehmen und anpassen
- Jede Abhängigkeit kostet: Updates, Sicherheits-Audits, Bundle-Größe, Breaking Changes

# 8.5 useHooks als Standard-Hook-Sammlung / useDebounce selbst implementiert

```typescript
import { useEffect, useState } from 'react'

export function useDebounce<T>(value: T, delay = 300): T {
    const [debounced, setDebounced] = useState<T>(value)

    useEffect(() => {
        const timer = setTimeout(() => setDebounced(value), delay)
        return () => clearTimeout(timer)
    }, [value, delay])

    return debounced
}
```

- Der Cleanup bricht den vorigen Timer ab: nur die letzte Änderung einer Serie setzt den Wert
- Generisch: der Rückgabetyp entspricht dem Typ des übergebenen Werts
- Verwendung identisch zur Bibliothek: `const debouncedTerm = useDebounce(term, 300)`

# 8.5 useHooks als Standard-Hook-Sammlung / Bewertung des Beispiels

- Aufwand: 8 Zeilen, ein Testfall mit Vitest und Fake Timers (`vi.useFakeTimers()`, `vi.advanceTimersByTime(300)`)
- Vorteil gegenüber der Bibliothek: volle Typisierung, keine Abhängigkeit, Anpassung möglich (z. B. `leading`-Option, Abbrechen)
- Nachteil: Wartung und Tests liegen beim Team
- Empfehlung im Seminar: für einfache Hooks wie `useDebounce` selbst schreiben oder kopieren, für Browser-API-Hooks mit Sonderfällen (`useMediaQuery`, `useNetworkState`, `useIntersectionObserver`) eine Bibliothek nutzen
- Entscheidend ist ein **Team-Standard**: ein Ort für Hooks (`src/hooks/`), keine doppelten Implementierungen
