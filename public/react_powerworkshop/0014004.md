# 14.4 Build, Deployment und Produktion / Bundle-Größe und Performance analysieren

## Bundle analysieren

- Erst messen, dann optimieren: `rollup-plugin-visualizer` erzeugt eine Treemap aller Module im Bundle.

```bash
npm install -D rollup-plugin-visualizer
```

```typescript
// vite.config.ts
import { visualizer } from 'rollup-plugin-visualizer'

export default defineConfig({
  plugins: [react(), visualizer({ open: true, gzipSize: true })],
})
```

- Nach `npm run build` öffnet sich `stats.html`: große Rechtecke sind große Abhängigkeiten.
- Vite warnt bei Chunks über 500 kB (`build.chunkSizeWarningLimit`).

# 14.4 Build, Deployment und Produktion / Typische Ursachen großer Bundles

- Komplette Bibliotheken importiert statt einzelner Funktionen (z.B. alle Icons, ganz `lodash`).
- Schwere Bibliotheken auf der Startseite (Charts, Editoren, PDF, Karten) statt per `import()` bei Bedarf.
- Mehrere Bibliotheken mit gleicher Aufgabe (`moment` und `date-fns`, mehrere UI-Kits).
- Barrel-Dateien (`index.ts`), die Tree Shaking erschweren.
- Große Bilder und Fonts im Bundle statt optimiert (WebP/AVIF, `woff2`, Subsetting).
- Prüfen vor dem Hinzufügen: Größe auf bundlephobia.com, Alternativen mit ESM und Tree Shaking.

# 14.4 Build, Deployment und Produktion / Performance messen

- Lighthouse (Chrome DevTools): Gesamtbewertung und konkrete Empfehlungen, immer gegen `vite preview` oder die echte Seite messen.
- Core Web Vitals:
  - LCP (Largest Contentful Paint): Ladezeit des größten sichtbaren Elements, Ziel unter 2,5 s.
  - INP (Interaction to Next Paint): Reaktionszeit auf Eingaben, Ziel unter 200 ms.
  - CLS (Cumulative Layout Shift): unerwartete Layoutverschiebungen, Ziel unter 0,1.
- Reale Nutzerdaten sammelt man mit der Bibliothek `web-vitals`:

```typescript
import { onLCP, onINP, onCLS } from 'web-vitals'

onLCP(console.log)
onINP(console.log)
onCLS(console.log)
```

- Laufzeit-Probleme in React: React DevTools Profiler zeigt, welche Komponenten wie oft und wie lange rendern.
