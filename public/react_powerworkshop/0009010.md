# 9.10 HTTP, APIs und Server State / TanStack Query: Queries

## useQuery mit TypeScript

```typescript
import { useQuery } from '@tanstack/react-query'

type Todo = { id: number; todo: string; completed: boolean }
type TodosResponse = { todos: Todo[] }

async function fetchTodos(): Promise<Todo[]> {
    const res = await fetch('https://dummyjson.com/todos?limit=10')
    if (!res.ok) throw new Error(`HTTP ${res.status}`) // fetch wirft bei 4xx/5xx nicht selbst
    const json: TodosResponse = await res.json()
    return json.todos
}

export function TodoList() {
    const { data, isPending, isError, error } = useQuery({
        queryKey: ['todos'],
        queryFn: fetchTodos,
    })

    if (isPending) return <p>Laden…</p>
    if (isError) return <p role="alert">Fehler: {error.message}</p>

    return <ul>{data.map(t => <li key={t.id}>{t.todo}</li>)}</ul>
}
```

- `queryFn` muss ein Promise liefern und bei Fehlern **werfen**.
- Nach den Prüfungen auf `isPending` und `isError` ist `data` typsicher vorhanden.

## Status: isPending, isFetching, isError

- `isPending`: noch keine Daten im Cache (erstes Laden). In v5 der Nachfolger von `isLoading` aus v4.
- `isFetching`: irgendein Request läuft, auch ein Hintergrund-Refetch bei vorhandenen Daten.
- `isLoading`: `isPending && isFetching`, also erstes Laden mit laufendem Request.
- `isError` / `error`: der letzte Versuch ist fehlgeschlagen (nach Retries, Standard: 3 Versuche mit Backoff).
- `status` (`'pending' | 'error' | 'success'`) lässt sich wie die Discriminated Union aus 9.5 verwenden.
- Typisch: Daten anzeigen und bei `isFetching` einen kleinen Spinner zeigen, statt die Liste auszublenden.

## Query Keys

- Der `queryKey` ist ein Array und identifiziert die Daten im Cache. Er muss alle Variablen enthalten, von denen die `queryFn` abhängt.
- Ändert sich ein Wert im Key, wird automatisch eine neue Query geladen (analog zur Dependency-Liste von `useEffect`).
- Konvention: vom Allgemeinen zum Speziellen.

```typescript
useQuery({ queryKey: ['todos'], queryFn: fetchTodos })                      // Liste
useQuery({ queryKey: ['todos', { completed }], queryFn: () => fetchTodos(completed) }) // gefiltert
useQuery({
    queryKey: ['todos', id],                                                 // Detail
    queryFn: () => fetchTodo(id),
    enabled: id !== undefined,                                               // nur laden, wenn id bekannt
})
```

- Keys werden strukturell verglichen, die Reihenfolge von Objekt-Eigenschaften spielt keine Rolle.
- Gemeinsames Präfix `['todos']` erlaubt später, alle zugehörigen Queries gemeinsam zu invalidieren.
