# 15.6 Best Practices und Architektur / Fehlerbehandlung und robuste Ladezustände

## Jeder Datenabruf hat vier Zustände

- Laden, Fehler, leer, erfolgreich: alle vier bewusst gestalten.
- TanStack Query (Kapitel 9) liefert `isPending`, `isError`, `error` und `refetch`.
- Skeletons statt Spinner, wenn die Struktur bekannt ist: das Layout springt nicht.
- Empty State mit Handlungsaufforderung ("Noch keine Todos. Lege das erste an.") statt leerer Fläche.
- Retry: Query wiederholt Abrufe standardmäßig dreimal; für Nutzer zusätzlich ein Button "Erneut versuchen".

```typescript
if (query.isPending) return <TodoSkeleton />
if (query.isError) return <ErrorMessage error={query.error} onRetry={() => query.refetch()} />
if (query.data.length === 0) return <EmptyState text="Noch keine Todos." />
return <TodoList todos={query.data} />
```

# 15.6 Best Practices und Architektur / Error Boundaries und Suspense

- Error Boundaries fangen Fehler beim Rendern im Teilbaum ab; Event-Handler und asynchroner Code werden nicht erfasst.
- Eine eigene Klassenkomponente ist nötig (einer der wenigen legitimen Fälle) oder das Paket `react-error-boundary`.
- Mehrere Boundaries setzen: eine pro Seite oder Widget, damit nicht die ganze App ausfällt.
- `Suspense` zeigt ein `fallback`, solange Teilbaum lädt (`lazy`, `useSuspenseQuery`, `use`).

```typescript
import { ErrorBoundary } from 'react-error-boundary'

<ErrorBoundary fallback={<p role="alert">Etwas ist schiefgelaufen.</p>}>
    <Suspense fallback={<TodoSkeleton />}>
        <TodoList />
    </Suspense>
</ErrorBoundary>
```

# 15.6 Best Practices und Architektur / Nutzerfreundliche Fehlermeldungen

- Fehler unterscheiden: Netzwerkfehler, 401/403, 404, 5xx, Validierungsfehler (Zod, Kapitel 11).
- Meldungen sagen, was passiert ist und was der Nutzer tun kann; keine Stacktraces oder rohen Serverantworten anzeigen.
- Fehlermeldungen mit `role="alert"` auszeichnen, damit Screenreader sie vorlesen.
- Technische Details in Logging/Monitoring (z. B. Sentry) senden, nicht in die UI.
- Mutationen: Fehler lokal am auslösenden Element anzeigen (`mutation.error`), nicht nur in der Konsole.
- Offline: `useQuery` kennt `fetchStatus: 'paused'`; einen Hinweis "Keine Verbindung" anzeigen.
