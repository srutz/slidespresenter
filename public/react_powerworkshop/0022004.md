
# 22.4 SemVer und npm (Zusatzthema) / Versionsvergleich und der API-Vertrag

## Wie Versionen verglichen werden (Präzedenz)

- Versionen werden Stelle für Stelle numerisch verglichen: `1.9.0 < 1.10.0 < 1.10.1`.
- Eine Version mit Pre-Release-Suffix ist immer "kleiner" als dieselbe Version ohne Suffix:

```
1.0.0-alpha < 1.0.0-alpha.1 < 1.0.0-beta < 1.0.0-rc.1 < 1.0.0
```

- Innerhalb der Pre-Release-Kennung wird wieder Feld für Feld verglichen (numerisch, wenn beide Felder Zahlen sind, sonst alphabetisch).

# 22.4 SemVer und npm (Zusatzthema) / Versionsvergleich und der API-Vertrag

## SemVer ist ein Vertrag, kein Automatismus

- SemVer funktioniert nur, wenn sich die Autoren einer Bibliothek **diszipliniert** daran halten - die Versionsnummer wird nicht automatisch korrekt vergeben, sie muss bewusst richtig gewählt werden.
- Der Vertrag bezieht sich immer auf die **öffentliche Schnittstelle** (public API): interne Implementierungsdetails dürfen sich ändern, ohne dass dies als brechende Änderung zählt.
- Nutzer einer Bibliothek können sich im Gegenzug darauf verlassen: Solange sich nur PATCH oder MINOR ändert, sollte ihr Code ohne Anpassung weiterlaufen.
- Diese Idee - Versionsnummern als verlässlicher, maschinenlesbarer Vertrag - ist die Grundlage dafür, dass Paketmanager wie **npm** Abhängigkeiten automatisch verwalten können.
