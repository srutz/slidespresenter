# 15.9 Best Practices und Architektur / Typische React Anti-Patterns (1)

## Abgeleiteter State und Effects für Datenfluss

```typescript
// schlecht: doppelter State, per Effect synchronisiert
const [todos, setTodos] = useState<Todo[]>([])
const [openCount, setOpenCount] = useState(0)
useEffect(() => {
    setOpenCount(todos.filter(t => !t.done).length)
}, [todos])

// gut: während des Renderns berechnen
const openCount = todos.filter(t => !t.done).length
```

- Effects sind für Synchronisation mit der Außenwelt (Timer, Subscriptions), nicht für Datenfluss zwischen State-Variablen.
- Daten laden per `useEffect` + `fetch`: besser TanStack Query (Kapitel 9).
- Reaktion auf Nutzeraktionen gehört in Event-Handler, nicht in Effects.

# 15.9 Best Practices und Architektur / Typische React Anti-Patterns (2)

## Index als Key und mutierter State

```typescript
// schlecht: Index als Key bei veränderlichen Listen
{todos.map((t, i) => <TodoItem key={i} todo={t} />)}
// gut
{todos.map(t => <TodoItem key={t.id} todo={t} />)}

// schlecht: State mutieren, React erkennt keine Änderung
todos.push(newTodo)
setTodos(todos)
// gut: neues Array
setTodos([...todos, newTodo])
```

- Mit Index als Key verschiebt sich State (z. B. Eingabefelder) beim Umsortieren oder Löschen auf falsche Einträge.
- Objekte und Arrays im State immer neu erzeugen (Kapitel 7, 12).

# 15.9 Best Practices und Architektur / Typische React Anti-Patterns (3)

## Architektur und Typen

- Server-State in globalem Store: Daten von der API in Zustand kopieren und selbst aktuell halten. Besser: TanStack Query (Kapitel 15.4).
- Riesige Komponenten: mehrere hundert Zeilen mit Laden, Logik und Darstellung. Besser: aufteilen in Container, Hook und kleine UI-Komponenten (Kapitel 15.2).
- Prop Drilling über viele Ebenen: Composition oder Store (Kapitel 15.5).
- Komponenten innerhalb von Komponenten definieren: sie werden bei jedem Rendern neu erzeugt und verlieren ihren State.
- `any` in TypeScript: schaltet die Typprüfung ab. Besser `unknown` mit Prüfung oder Zod-Schema (Kapitel 11).

```typescript
// schlecht
const data: any = await response.json()
// gut: zur Laufzeit validieren
const todos = z.array(TodoSchema).parse(await response.json())
```
