
# 22.2 SemVer und npm (Zusatzthema) / Das Format MAJOR.MINOR.PATCH

## Aufbau einer Versionsnummer

- Eine SemVer-Versionsnummer hat immer die Form:

```
MAJOR.MINOR.PATCH
z.B. 2.5.1
```

- **MAJOR** wird erhöht, wenn inkompatible (brechende) Änderungen an der öffentlichen Schnittstelle vorgenommen wurden.
- **MINOR** wird erhöht, wenn neue Funktionalität abwärtskompatibel hinzugefügt wurde.
- **PATCH** wird erhöht, wenn abwärtskompatible Fehlerkorrekturen vorgenommen wurden.

- Alle drei Zahlen sind nicht-negative Ganzzahlen und werden ohne führende Nullen geschrieben (`1.2.3`, nicht `1.02.3`).

# 22.2 SemVer und npm (Zusatzthema) / Das Format MAJOR.MINOR.PATCH

## Beispiele

```
1.4.2  →  1.4.3   Bugfix, nichts weiter geändert (PATCH)
1.4.2  →  1.5.0   Neue Funktion, alter Code läuft weiter (MINOR)
1.4.2  →  2.0.0   Bestehende API wurde geändert oder entfernt (MAJOR)
```

- Wichtig: Nach einer MAJOR-Erhöhung werden MINOR und PATCH wieder auf `0` zurückgesetzt (`1.9.3 → 2.0.0`, nicht `2.9.3`).
- Nach einer MINOR-Erhöhung wird PATCH auf `0` zurückgesetzt (`1.4.9 → 1.5.0`).
- Diese einfache Regel erlaubt es, allein anhand der Differenz zweier Versionsnummern das **Risiko** eines Updates einzuschätzen.
