# 7.7 Hooks und moderne React Patterns / useReducer() für komplexeren lokalen State

## Wann useReducer statt useState?

- `useState` reicht für einzelne, unabhängige Werte (Flag, Eingabefeld, Zähler)
- `useReducer` lohnt sich, wenn
    - mehrere Werte **zusammenhängen** und gemeinsam geändert werden
    - der nächste State vom vorherigen abhängt und es viele Arten von Änderungen gibt
    - die Übergänge **benannt** und an einer Stelle testbar sein sollen
- Die Reducer-Funktion ist eine reine Funktion ohne React-Abhängigkeit und lässt sich ohne Rendern testen (Vitest)
- `dispatch` hat eine stabile Identität und kann gefahrlos an Kinder weitergegeben werden
- Bereits gesehen: HTTP-Zustände (loading/data/error) in 7.6, dort mit untypisierten Daten

# 7.7 Hooks und moderne React Patterns / useReducer() Warenkorb: State und Actions

## Actions als Discriminated Union

```typescript
type CartItem = { id: string; name: string; price: number; quantity: number }

type CartState = { items: CartItem[] }

type CartAction =
    | { type: 'add'; item: Omit<CartItem, 'quantity'> }
    | { type: 'remove'; id: string }
    | { type: 'setQuantity'; id: string; quantity: number }
    | { type: 'clear' }
```

- Das Feld `type` ist der Diskriminator: TypeScript weiß im `case`, welche weiteren Felder existieren
- Actions beschreiben **was passiert ist**, nicht wie der State aussieht

# 7.7 Hooks und moderne React Patterns / useReducer() Warenkorb: Reducer und Komponente

```typescript
function cartReducer(state: CartState, action: CartAction): CartState {
    switch (action.type) {
        case 'add': {
            const existing = state.items.find(i => i.id === action.item.id)
            if (existing) {
                return { items: state.items.map(i =>
                    i.id === existing.id ? { ...i, quantity: i.quantity + 1 } : i) }
            }
            return { items: [...state.items, { ...action.item, quantity: 1 }] }
        }
        case 'remove':
            return { items: state.items.filter(i => i.id !== action.id) }
        case 'setQuantity':
            return { items: state.items.map(i =>
                i.id === action.id ? { ...i, quantity: action.quantity } : i) }
        case 'clear':
            return { items: [] }
    }
}
```

# 7.7 Hooks und moderne React Patterns / useReducer() Warenkorb: Verwendung

```typescript
export function Cart() {
    const [state, dispatch] = useReducer(cartReducer, { items: [] })
    const total = state.items.reduce((sum, i) => sum + i.price * i.quantity, 0)

    return (
        <div>
            <button onClick={() => dispatch({ type: 'add', item: { id: '1', name: 'Buch', price: 25 } })}>
                Buch hinzufügen
            </button>
            {state.items.map(i => (
                <p key={i.id}>
                    {i.name} x {i.quantity}
                    <button onClick={() => dispatch({ type: 'remove', id: i.id })}>Entfernen</button>
                </p>
            ))}
            <p>Summe: {total} EUR</p>
        </div>
    )
}
```

- Abgeleitete Werte (`total`) werden beim Rendern berechnet und nicht im State gespeichert
- Ohne `default`-Zweig prüft TypeScript, dass alle Actions behandelt werden (Rückgabetyp `CartState`)
