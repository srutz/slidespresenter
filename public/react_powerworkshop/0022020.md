
# 22.20 SemVer und npm (Zusatzthema) / npm version

## Die eigene Paketversion hochzählen

```bash
npm version patch   # 1.4.2 -> 1.4.3
npm version minor   # 1.4.2 -> 1.5.0
npm version major   # 1.4.2 -> 2.0.0
npm version 2.1.0-beta.1   # exakte Version setzen
```

- Aktualisiert die `version` in `package.json` (und `package-lock.json`) automatisch gemäß SemVer.
- Erstellt dabei standardmäßig auch einen **git commit** und einen passenden **git tag** (z. B. `v1.4.3`).
- Typischer Bestandteil eines Release-Workflows, meist gefolgt von `npm publish`, um die neue Version in die Registry hochzuladen.

- Werkzeuge wie **semantic-release** oder **changesets** gehen noch einen Schritt weiter: Sie leiten aus den Commit-Nachrichten (z. B. "Conventional Commits") automatisch ab, ob PATCH, MINOR oder MAJOR fällig ist.
