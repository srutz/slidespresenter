
# 12.4 State Management mit Zustand / Zustand – Alternative zu Redux

## Was ist Zustand?

- **Zustand** (japanisch für „state") ist eine schlanke State-Management-Bibliothek für React.
- Kein Provider, kein Reducer, kein Boilerplate – ein einziger `create`-Aufruf genügt.
- Der Store ist ein Hook, der direkt in jeder Komponente verwendet werden kann.
- Unterstützt TypeScript out-of-the-box.

Installation:

```bash
npm install zustand
```

## Vergleich Redux Toolkit vs. Zustand

| | Redux Toolkit | Zustand |
|---|---|---|
| Boilerplate | mittel (Slice, Provider, Selektoren) | minimal |
| DevTools | Redux DevTools | Redux DevTools (optional) |
| Provider | erforderlich | **nicht nötig** |
| Immer | eingebaut | optional als Middleware |
| Bundle-Größe | ~12 kB | ~1 kB |

# 12.4 State Management mit Zustand / Zustand – Store erstellen

## Einfacher Counter-Store

```typescript
import { create } from 'zustand'

type CounterStore = {
    count: number
    increment: () => void
    decrement: () => void
    reset: () => void
}

export const useCounterStore = create<CounterStore>((set) => ({
    count: 0,
    increment: () => set((state) => ({ count: state.count + 1 })),
    decrement: () => set((state) => ({ count: state.count - 1 })),
    reset: () => set({ count: 0 }),
}))
```

- `create` nimmt eine Funktion, die den initialen State und die Aktionen zurückgibt.
- `set` aktualisiert den State – entweder direkt (`{ count: 0 }`) oder via Updater-Funktion.
- Das Ergebnis ist ein **React-Hook** (`useCounterStore`), der direkt in Komponenten eingesetzt wird.

# 12.4 State Management mit Zustand / Zustand – Store verwenden

## Komponenten lesen und verändern den Store

```typescript
import { useCounterStore } from './counterStore'

export function Counter() {
    const count = useCounterStore((state) => state.count)
    const increment = useCounterStore((state) => state.increment)
    const decrement = useCounterStore((state) => state.decrement)
    const reset = useCounterStore((state) => state.reset)

    return (
        <div>
            <button onClick={decrement}>-</button>
            <span>{count}</span>
            <button onClick={increment}>+</button>
            <button onClick={reset}>Reset</button>
        </div>
    )
}
```

- Der Selektor `(state) => state.count` sorgt dafür, dass die Komponente **nur** bei Änderung von `count` neu rendert.
- Aktionen wie `increment` sind stabile Referenzen – kein `useCallback` nötig.
- Es braucht **keinen Provider** – der Store ist global verfügbar.

# 12.4 State Management mit Zustand / Zustand – Store mit komplexem State

## Todo-Liste ohne Immer

```typescript
import { create } from 'zustand'

type Todo = { id: number; text: string; done: boolean }

type TodoStore = {
    todos: Todo[]
    addTodo: (text: string) => void
    toggleTodo: (id: number) => void
    removeTodo: (id: number) => void
}

let nextId = 1

export const useTodoStore = create<TodoStore>((set) => ({
    todos: [],
    addTodo: (text) =>
        set((state) => ({
            todos: [...state.todos, { id: nextId++, text, done: false }],
        })),
    toggleTodo: (id) =>
        set((state) => ({
            todos: state.todos.map((t) =>
                t.id === id ? { ...t, done: !t.done } : t
            ),
        })),
    removeTodo: (id) =>
        set((state) => ({
            todos: state.todos.filter((t) => t.id !== id),
        })),
}))
```

- Ohne Immer müssen Objekte und Arrays **immutabel** aktualisiert werden (Spread, `map`, `filter`).
- Bei tief verschachtelten Strukturen wird das Code schnell unübersichtlich → hier hilft Immer.
