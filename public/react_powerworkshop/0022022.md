
# 22.22 SemVer und npm (Zusatzthema) / Zusammenfassung und Best Practices

## Checkliste für die Versionsverwaltung

- `package-lock.json` immer committen - sie garantiert reproduzierbare Installationen.
- In CI/CD und Docker-Builds `npm ci` statt `npm install` verwenden.
- Regelmäßig `npm outdated` und `npm audit` prüfen, statt Updates auf den letzten Moment zu verschieben.
- `npm update` reicht für PATCH/MINOR - Major-Updates bewusst und einzeln durchführen, danach gründlich testen.
- Bei Versionskonflikten zuerst `npm ls` / `npm why` zur Analyse nutzen, dann `npm dedupe` versuchen - `overrides` nur als letztes Mittel und zeitlich befristet einsetzen.
- Bibliotheken, die man selbst veröffentlicht, konsequent mit `npm version` und SemVer-konformen Versionssprüngen pflegen - das ist der Vertrag, auf den sich die eigenen Nutzer verlassen.
