
# 12.19 State Management mit Zustand / Alternativen zu Redux – useLocalStorage

## useLocalStorage als globaler State

- `useLocalStorage` aus der Bibliothek `usehooks-ts` verhält sich wie `useState`, speichert den Wert aber im `localStorage`.
- Der entscheidende Trick: der Hook lauscht auf das `storage`-Event des Browsers – dadurch synchronisieren sich alle Komponenten (und sogar Browser-Tabs), die denselben Key verwenden, automatisch.
- Das macht `useLocalStorage` zu einer einfachen Form von globalem State ohne Provider, Reducer oder Store.

```typescript
import { useLocalStorage } from 'usehooks-ts'

export function Counter() {
    const [count, setCount] = useLocalStorage('counter', 0)
    return (
        <div>
            <button onClick={() => setCount((c) => c - 1)}>-</button>
            <span>{count}</span>
            <button onClick={() => setCount((c) => c + 1)}>+</button>
        </div>
    )
}
```

- Zwei beliebige Komponenten, die `useLocalStorage('counter', 0)` aufrufen, teilen denselben Wert – öffnet man die App in einem zweiten Tab, wird auch dort der Zähler aktualisiert.

## Wann eignet sich dieser Ansatz?

- State, der ohnehin persistiert werden soll (Einstellungen, Theme, Sprache, Login-Token).
- Kleine bis mittlere Apps, bei denen ein vollständiges State-Management-Tool überdimensioniert wäre.
- Rapid Prototyping: kein Setup, kein Boilerplate – einfach den Hook einbinden.

## Einschränkungen

- Nur für serialisierbaren State geeignet (JSON-fähige Werte).
- Kein zentrales DevTool wie Redux DevTools.
- Bei sehr häufigen Schreiboperationen (z. B. Live-Input) ist `localStorage` langsamer als In-Memory-State.
- Sensible Daten (z. B. Passwörter) gehören **nicht** in den `localStorage`.
