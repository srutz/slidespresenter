# 6.6 React mit TypeScript / API-Daten und asynchrone Ergebnisse typisieren

## Typen für API-Responses

- Eine async-Funktion liefert immer ein Promise<T>.
- response.json() liefert zur Compile-Zeit any bzw. unknown-ähnliche Daten. Der Typ muss selbst zugesichert werden.

```typescript
type User = { id: number; name: string; email: string }

async function fetchJson<T>(url: string): Promise<T> {
    const response = await fetch(url)
    if (!response.ok) {
        throw new Error(`HTTP ${response.status}`)
    }
    return (await response.json()) as T
}

const users = await fetchJson<User[]>('/api/users')
```

- Achtung: `as T` ist nur eine Behauptung. Ob der Server wirklich diese Form liefert, prüft TypeScript nicht.

## Zod-Schema als Single Source of Truth

- Ein Zod-Schema validiert zur Laufzeit und liefert den Typ gleich mit (z.infer).

```typescript
import { z } from 'zod';

const UserSchema = z.object({
    id: z.number(),
    name: z.string(),
    email: z.email(),
})
type User = z.infer<typeof UserSchema>

async function fetchUsers(): Promise<User[]> {
    const response = await fetch('/api/users')
    const data: unknown = await response.json()
    return z.array(UserSchema).parse(data)
}
```

- Nutzen: Typ und Validierung können nicht auseinanderlaufen. Dasselbe Schema wird später für Formulare (React Hook Form) wiederverwendet.

## unknown statt any

- any schaltet die Typprüfung ab und "infiziert" den umgebenden Code.
- unknown verlangt eine Prüfung (Narrowing oder Parsing), bevor der Wert verwendet wird.

```typescript
function handle(data: unknown) {
    // data.name  -> Fehler
    if (typeof data === 'object' && data !== null && 'name' in data) {
        console.log(data.name)
    }
}

try {
    await fetchUsers()
} catch (error) {   // mit strict: error ist unknown
    if (error instanceof Error) console.error(error.message)
}
```
