# 24.1 Anhang: JavaScript Primer / Arrow Functions

## Arrow Functions

- Arrow Functions sind eine kompaktere Schreibweise für Funktionen.
- Wichtigster Unterschied zu `function`: Arrow Functions binden **kein eigenes `this`** — sie erben `this` aus dem umgebenden Scope.
- Ideal für Callbacks, z. B. in `map`, `filter` oder `setTimeout`.

```typescript
// Klassische Funktion
function add(a: number, b: number): number {
  return a + b
}

// Arrow Function – Langform
const add = (a: number, b: number): number => {
  return a + b
}

// Arrow Function – Kurzform (implizites return bei einzelnem Ausdruck)
const add = (a: number, b: number) => a + b

// Ein Parameter: Klammern optional
const double = (x: number) => x * 2

// Kein Parameter
const greet = () => 'Hallo!'

// Objekt zurückgeben: in runde Klammern einwickeln
const makeUser = (name: string) => ({ name, active: true })
```

# 24.2 Anhang: JavaScript Primer / Spread-Operator

## Arrays und Objekte kopieren

- Der Spread-Operator `...` verteilt die Elemente eines Arrays oder die Properties eines Objekts.
- Wichtig: Spread erzeugt nur eine **flache Kopie** (shallow copy) — verschachtelte Objekte werden nicht tief kopiert.

```typescript
// Arrays zusammenführen / kopieren
const a = [1, 2, 3]
const b = [4, 5, 6]
const combined = [...a, ...b]       // [1, 2, 3, 4, 5, 6]
const copy = [...a]                 // neue Referenz, gleiche Werte

// Objekte kopieren und überschreiben
const user = { name: 'Max', age: 30, active: true }
const updated = { ...user, age: 31 }          // age überschrieben
const extended = { ...user, role: 'admin' }   // neue Property hinzugefügt

// Flache Kopie – Achtung bei verschachtelten Objekten
const original = { name: 'Max', address: { city: 'Berlin' } }
const shallow = { ...original }
shallow.address.city = 'München'   // ändert auch original.address.city !
```

```typescript
// Tiefe Kopie – falsche Lösung mit JSON
const deep = JSON.parse(JSON.stringify(original))

// Oder mit structuredClone (modern, nativ)
const deep2 = structuredClone(original)
```

# 24.3 Anhang: JavaScript Primer / Rest-Operator und Destructuring

## Rest-Operator und Destructuring

- Der Rest-Operator `...` sammelt verbleibende Elemente in einem Array oder Objekt.
- Destructuring extrahiert Werte aus Arrays oder Objekten in einzelne Variablen.

```typescript
// Array-Destructuring
const [first, second, ...rest] = [10, 20, 30, 40, 50]
// first = 10, second = 20, rest = [30, 40, 50]

// Objekt-Destructuring
const { name, age, ...remaining } = { name: 'Max', age: 30, city: 'Berlin', active: true }
// name = 'Max', age = 30, remaining = { city: 'Berlin', active: true }

// Umbenennen beim Destructuring
const { name: userName, age: userAge } = user

// Defaultwerte
const { role = 'guest', name: n } = user

// In Funktionsparametern
function greet({ name, age = 0 }: { name: string; age?: number }) {
  return `${name} ist ${age} Jahre alt`
}

// Rest-Parameter in Funktionen
function sum(first: number, ...rest: number[]) {
  return rest.reduce((acc, n) => acc + n, first)
}
sum(1, 2, 3, 4)  // 10
```

# 24.4 Anhang: JavaScript Primer / Getter und Setter

## Getter und Setter

- Getter und Setter ermöglichen es, den Zugriff auf Properties zu kontrollieren.
- Mit `get` wird eine Property lesbar gemacht, mit `set` schreibbar — beides sieht aus wie ein normaler Property-Zugriff.

```typescript
// In einem Objekt-Literal
const circle = {
  _radius: 5,
  get radius() { return this._radius },
  set radius(v: number) {
    if (v < 0) throw new Error('Radius darf nicht negativ sein')
    this._radius = v
  },
  get area() { return Math.PI * this._radius ** 2 }
}

circle.radius = 10        // ruft setter auf
console.log(circle.area)  // ruft getter auf, kein ()
```

```typescript
// In einer Klasse
class Temperature {
  private _celsius: number

  constructor(celsius: number) { this._celsius = celsius }

  get fahrenheit() { return this._celsius * 9/5 + 32 }
  set fahrenheit(f: number) { this._celsius = (f - 32) * 5/9 }

  get celsius() { return this._celsius }
  set celsius(v: number) { this._celsius = v }
}

const t = new Temperature(100)
console.log(t.fahrenheit)  // 212
t.fahrenheit = 32
console.log(t.celsius)     // 0
```

# 24.5 Anhang: JavaScript Primer / Promises

## Promises

- Ein `Promise` repräsentiert einen Wert der in der Zukunft verfügbar sein wird (oder einen Fehler).
- Zustände: `pending` → `fulfilled` oder `rejected`.
- `.then()` für Ergebnisse, `.catch()` für Fehler, `.finally()` läuft immer.

```typescript
// Promise erstellen
const wait = (ms: number) => new Promise<void>(resolve => setTimeout(resolve, ms))

// Promise-Kette
fetch('/api/user')
  .then(res => res.json())
  .then((user: User) => console.log(user.name))
  .catch(err => console.error('Fehler:', err))
  .finally(() => console.log('Fertig'))

// Mehrere Promises parallel
const [users, posts] = await Promise.all([
  fetch('/api/users').then(r => r.json()),
  fetch('/api/posts').then(r => r.json()),
])

// Erstes erfolgreiches Ergebnis
const fastest = await Promise.race([fetchFromMirror1(), fetchFromMirror2()])
```

# 24.6 Anhang: JavaScript Primer / async / await

## async / await

- `async`/`await` ist syntaktischer Zucker über Promises — der Code sieht synchron aus, ist es aber nicht.
- Eine `async`-Funktion gibt immer ein `Promise` zurück.
- `await` kann nur innerhalb einer `async`-Funktion verwendet werden.
- Fehlerbehandlung mit `try/catch` statt `.catch()`.

```typescript
async function loadUser(id: number): Promise<User> {
  const res = await fetch(`/api/users/${id}`)
  if (!res.ok) throw new Error(`HTTP ${res.status}`)
  return res.json()
}

// Fehlerbehandlung
async function loadSafe(id: number) {
  try {
    const user = await loadUser(id)
    console.log(user.name)
  } catch (err) {
    console.error('Konnte User nicht laden:', err)
  } finally {
    console.log('Anfrage abgeschlossen')
  }
}

// Arrow Function als async-Callback
const init = async () => {
  try {
    const data = await fetchData()
    console.log(data)
  } catch (e) {
    console.error(e)
  }
}
```

# 24.7 Anhang: JavaScript Primer / ES-Module Export

## Export

- JavaScript-Dateien können Werte exportieren damit andere Dateien sie importieren können.
- **Named Export**: beliebig viele pro Datei, Import-Name muss übereinstimmen (oder umbenannt werden).
- **Default Export**: genau einer pro Datei, Import-Name ist frei wählbar.

```typescript
// math.ts – Named Exports
export const PI = 3.14159

export function add(a: number, b: number) { return a + b }

export class Calculator {
  multiply(a: number, b: number) { return a * b }
}

// Gebündelter Export am Ende der Datei – gleichwertig
const subtract = (a: number, b: number) => a - b
const divide   = (a: number, b: number) => a / b
export { subtract, divide }
```

```typescript
// user.ts – Default Export
export default class UserService {
  getUser(id: number) { /* ... */ }
}

// Oder: anonyme Funktion / Objekt als Default
export default function fetchAll() { /* ... */ }
```

# 24.8 Anhang: JavaScript Primer / ES-Module Import

## Import

- Named Imports stehen in geschweiften Klammern `{ }`, Default Imports ohne.
- Beide können in derselben Import-Zeile kombiniert werden.

```typescript
// Named Imports
import { PI, add, Calculator } from './math'

// Named Import umbenennen
import { add as sum } from './math'

// Alles als Namespace importieren
import * as Math from './math'
Math.add(1, 2)

// Default Import – Name frei wählbar
import UserService from './user'
import MeinService from './user'   // gleichwertig, anderer lokaler Name

// Default + Named in einer Zeile
import UserService, { Role, Permission } from './user'
```

```typescript
// Dynamischer Import – lädt das Modul erst zur Laufzeit (Code Splitting)
const { add } = await import('./math')

// Lazy Loading: Modul nur bei Bedarf laden
button.onclick = async () => {
  const { renderChart } = await import('./chart')
  renderChart()
}
```
