
# 11.11 Formulare und Validierung / Zod — Schema-Validierung

## Was ist Zod?

- **Zod** ist eine TypeScript-first Schema-Library zur Laufzeit-Validierung von Daten.
- Man beschreibt die erwartete Struktur einmal als Schema — Zod erzeugt daraus automatisch den passenden TypeScript-Typ.
- Einsatzgebiete: Formulare, API-Responses, URL-Parameter, Config-Dateien, Environment-Variablen.

```bash
npm install zod
```

```typescript
import { z } from 'zod'

const UserSchema = z.object({
    name: z.string().min(2, 'Mindestens 2 Zeichen'),
    age:  z.number().int().min(0).max(120),
    email: z.string().email('Ungültige E-Mail'),
    role: z.enum(['admin', 'user', 'guest']),
})

// TypeScript-Typ kostenlos ableiten
type User = z.infer<typeof UserSchema>

// Validierung zur Laufzeit
const result = UserSchema.safeParse({ name: 'Ana', age: 30, email: 'a@b.de', role: 'admin' })
if (result.success) {
    console.log(result.data)   // vollständig typisiert
} else {
    console.log(result.error.flatten())
}
```

## Zod — Wichtige Typen und Methoden

```typescript
import { z } from 'zod'

// Primitive
z.string()          // string
z.number()          // number
z.boolean()         // boolean
z.date()            // Date
z.undefined()
z.null()

// Strings verfeinern
z.string().min(3).max(100)
z.string().email()
z.string().url()
z.string().regex(/^\d{5}$/, 'PLZ muss 5 Ziffern haben')

// Zahlen verfeinern
z.number().int().positive()
z.number().min(0).max(100)

// Optionale und nullable Felder
z.string().optional()          // string | undefined
z.string().nullable()          // string | null
z.string().nullish()           // string | null | undefined

// Arrays und Objekte
z.array(z.string()).min(1)
z.object({ id: z.number(), label: z.string() })

// Enum
z.enum(['draft', 'published', 'archived'])

// Union
z.union([z.string(), z.number()])
// Kurzform:
z.string().or(z.number())
```

## Zod — API-Responses validieren

- Daten aus `fetch` sind zur Laufzeit untypisiert. Zod schließt die Lücke zwischen Laufzeit und TypeScript.
- `safeParse` wirft keine Exception — ideal für fetch-Antworten, bei denen man Fehler behandeln will.
- Typischer Einsatz: Custom Hook, der die Response validiert und typisiert zurückgibt.

```typescript
import { z } from 'zod'

const ProductSchema = z.object({
    id: z.number(),
    title: z.string(),
    price: z.number().positive(),
    inStock: z.boolean(),
})

type Product = z.infer<typeof ProductSchema>

async function fetchProduct(id: number): Promise<Product> {
    const res = await fetch(`/api/products/${id}`)
    const json = await res.json()
    // wirft ZodError wenn die Struktur nicht passt
    return ProductSchema.parse(json)
}
```

## Zod — Transformationen und Defaults

- `.transform()` wandelt einen validierten Wert um, z. B. String → Date oder Trimmen.
- `.default()` setzt einen Standardwert, wenn ein Feld fehlt oder `undefined` ist.
- `.preprocess()` läuft **vor** der Validierung — nützlich für Typen-Koercion (z. B. Formular-Strings zu Zahlen).

```typescript
import { z } from 'zod'

const FormSchema = z.object({
    // leere Strings zu undefined machen, dann optional behandeln
    nickname: z.string().trim().optional(),

    // Formular liefert immer Strings — zu Zahl konvertieren
    age: z.preprocess(
        (val) => (val === '' ? undefined : Number(val)),
        z.number().int().min(0)
    ),

    // ISO-String automatisch zu Date-Objekt
    birthday: z.string().transform((s) => new Date(s)),

    // Feld kann fehlen, Default greift
    role: z.enum(['user', 'admin']).default('user'),
})

type FormData = z.infer<typeof FormSchema>
// { nickname?: string; age: number; birthday: Date; role: 'user' | 'admin' }
```
