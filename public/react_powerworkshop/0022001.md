
# 22.1 SemVer und npm (Zusatzthema) / Warum Versionsnummern?

## Das Grundproblem

- Software wird ständig weiterentwickelt: Fehler werden behoben, Funktionen kommen hinzu, APIs ändern sich.
- Sobald ein Software-Baustein (eine Bibliothek, ein Modul, ein Service) von anderem Code verwendet wird, entsteht eine **Abhängigkeit**.
- Ändert sich der Baustein, muss der abhängige Code wissen: "Kann ich einfach aktualisieren, oder bricht dabei etwas?"

- Ohne klare Regeln bleibt nur eine Möglichkeit: Jede neue Version manuell ausprobieren und hoffen, dass nichts kaputt geht.

# 22.1 SemVer und npm (Zusatzthema) / Warum Versionsnummern?

## Die Lösung: ein Versprechen in der Versionsnummer

- **Semantic Versioning (SemVer)** ist eine Konvention, bei der die Versionsnummer selbst Auskunft über die Art der Änderung gibt.
- Man erkennt allein an der Nummer, ob eine neue Version:
  - garantiert kompatibel ist,
  - neue, aber abwärtskompatible Funktionen bringt,
  - oder bestehenden Code brechen kann.
- SemVer ist kein Werkzeug und kein Produkt, sondern eine **Vereinbarung** zwischen den Autoren einer Software und ihren Nutzern.
- Der Standard ist sprachunabhängig und wird unter [semver.org](https://semver.org) gepflegt.
