# 8.6 useHooks als Standard-Hook-Sammlung / Externe Hooks bewerten

## Kriterien

- **API:** klar, minimal, konsistent mit React-Konventionen (Tupel wie `useState`, stabile Funktionen)
- **Typisierung:** mitgelieferte TypeScript-Typen, sinnvolle Generics
- **Abhängigkeiten:** keine oder wenige, Peer-Dependency passt zu React 19
- **Wartung:** letzte Releases, offene Issues, Reaktion auf Bugs, React-19-Kompatibilität
- **Bundle-Größe:** Tree-Shaking, einzelne Imports (bundlephobia / `vite build` prüfen)
- **SSR-Sicherheit:** kein Zugriff auf `window` beim Rendern
- **Tests:** vorhandene Tests der Bibliothek; eigene Tests für die Nutzung

# 8.6 useHooks als Standard-Hook-Sammlung / Checkliste und Einordnung

## Checkliste vor der Übernahme

- Brauchen wir den Hook wirklich, oder reicht React/CSS/Browser-API?
- Aktive Pflege und Kompatibilität mit unserer React-Version geprüft?
- Typen vorhanden, Nutzung im `strict`-Modus fehlerfrei?
- Quellcode gelesen (er ist meist kurz)? Cleanup und Edge Cases vorhanden?
- Aufwand zum Ersetzen oder Kopieren im Notfall gering?

## Einordnung useHooks

- Die Sammlung ist übersichtlich und didaktisch gut, wird aber nach unserem Kenntnisstand nur sporadisch weiterentwickelt (Experimental-Zweig, README nennt React 18+): vor dem Einsatz Aktivität auf GitHub prüfen
- Der Code ist klein: Kopieren in das eigene Projekt ist eine sinnvolle Option

## Alternativen

- `usehooks-ts`: TypeScript-first, aktiv gepflegt, ähnlicher Umfang
- `react-use`: sehr umfangreich, aber große Oberfläche und weniger aktiv
- Je nach Bedarf: TanStack Query (Server State), Zustand (globaler State), React Hook Form (Formulare)
