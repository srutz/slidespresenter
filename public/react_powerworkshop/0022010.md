
# 22.10 SemVer und npm (Zusatzthema) / Weitere Versions-Ranges

## x-Ranges, Vergleichsoperatoren, Kombinationen

```
1.2.x      jede Version 1.2.*  (äquivalent zu ~1.2.0)
1.x        jede Version 1.*    (äquivalent zu ^1.0.0)
*  bzw. "" jede Version
>=1.2.3    Version 1.2.3 oder neuer
<2.0.0     jede Version kleiner als 2.0.0
1.2.3 - 2.3.4   Bereich (inklusive) von 1.2.3 bis 2.3.4
```

- Mehrere Bedingungen mit Leerzeichen werden **UND**-verknüpft: `>=1.2.3 <2.0.0`.
- Mit `||` können Bereiche **ODER**-verknüpft werden: `^1.0.0 || ^2.0.0` (Version 1.x oder 2.x wird akzeptiert).

# 22.10 SemVer und npm (Zusatzthema) / Weitere Versions-Ranges

## Sonderfälle bei der Installation

```
latest     Tag, das i. d. R. auf die neueste stabile Version zeigt
next       gängiger Tag für Vorabversionen (nicht Teil des SemVer-Standards selbst)
1.2.3-beta.1   npm installiert Pre-Releases standardmäßig nur, wenn explizit danach gefragt wird
```

- `npm install react@latest` installiert die aktuellste Version und schreibt sie mit `^` in die `package.json`.
- `npm install react@1.2.3` pinnt exakt diese Version.
- Distribution-Tags wie `latest` oder `next` sind eine npm-Funktion, kein Bestandteil des SemVer-Standards - sie zeigen jeweils auf eine bestimmte SemVer-Version.
