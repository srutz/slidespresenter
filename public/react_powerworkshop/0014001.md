# 14.1 Build, Deployment und Produktion / Development vs. Production Build

## Die drei Vite-Kommandos

```bash
npm run dev       # vite: Dev-Server mit HMR, Module werden einzeln ausgeliefert
npm run build     # vite build: optimierter Production Build nach dist/
npm run preview   # vite preview: lokaler Server, der dist/ ausliefert
```

- `vite` nutzt im Dev-Betrieb native ES-Module des Browsers, es wird nichts gebündelt: schneller Start, Hot Module Replacement.
- `vite build` bündelt mit Rollup (Vite 7) bzw. Rolldown (neuere Vite-Versionen) und optimiert für Produktion.
- `vite preview` ist nur zum Testen des Builds gedacht, kein Produktionsserver.
- Typische Skripte in `package.json`: `"build": "tsc -b && vite build"` prüft zusätzlich die Typen.

# 14.1 Build, Deployment und Produktion / Unterschiede der Builds

| | Development | Production |
|---|---|---|
| Code | unminifiziert, Einzelmodule | minifiziert, gebündelt, Chunks |
| Tree Shaking | nein | ja, ungenutzter Code entfällt |
| React | Dev-Build mit Warnungen, StrictMode-Doppelrender | Production-Build ohne Warnungen, schneller |
| Dateinamen | Modulpfade | Content-Hash (`index-a1b2c3.js`) |
| Source Maps | ja | standardmäßig nein |
| `import.meta.env.DEV` | `true` | `false` |

- Performance messen und testen immer am Production Build (`build` + `preview`), nie im Dev-Server.
- Bugs, die nur in Produktion auftreten, werden so lokal reproduzierbar.

# 14.1 Build, Deployment und Produktion / Der dist-Ordner

```bash
dist/
  index.html
  assets/
    index-DiwrgTda.js     # Anwendungscode
    vendor-B3x9Q1aZ.js    # Bibliotheken
    index-C7Yp2kLm.css    # CSS (Tailwind)
  favicon.svg             # Dateien aus public/
```

- `dist/` besteht nur aus statischen Dateien: kein Node.js auf dem Server nötig.
- Dateien aus `public/` werden unverändert kopiert und unter `/` ausgeliefert.
- Der Hash im Dateinamen ändert sich mit dem Inhalt und ermöglicht langes Caching.
- `dist/` gehört in die `.gitignore` und wird in der CI neu gebaut.
