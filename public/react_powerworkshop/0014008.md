# 14.8 Build, Deployment und Produktion / CI/CD-Grundlagen

## Pipeline-Stufen

- Continuous Integration (CI): jede Änderung wird automatisch gebaut und geprüft.
- Continuous Delivery/Deployment (CD): geprüfte Änderungen werden automatisch bereitgestellt.
- Typische Stufen, jeweils nur bei grüner Vorstufe:

1. `npm ci` (Abhängigkeiten reproduzierbar installieren)
2. `npm run lint`
3. `npx tsc --noEmit` (Typecheck)
4. `npx vitest run` (Tests, vgl. Kapitel 13)
5. `npm run build`
6. Deploy (Preview bei Pull Request, Produktion bei Merge in `main`)

- Das Build-Artefakt (`dist/` bzw. Docker-Image) wird einmal gebaut und unverändert durch die Umgebungen befördert.

# 14.8 Build, Deployment und Produktion / GitHub Actions Beispiel

```yaml
# .github/workflows/deploy.yml
name: Build and Deploy
on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run lint
      - run: npx tsc --noEmit
      - run: npx vitest run
      - run: npm run build
        env:
          VITE_API_URL: ${{ vars.API_URL }}
      - uses: actions/upload-artifact@v4
        with:
          name: dist
          path: dist/
```

# 14.8 Build, Deployment und Produktion / Umgebungen, Secrets und Rollback

- Umgebungen (GitHub: Environments): `staging` und `production` mit eigenen Variablen, Freigabe durch Reviewer möglich.
- Öffentliche Konfiguration als `vars`, Zugangsdaten für den Deploy (Hoster-Token, SSH-Key, Registry-Passwort) als `secrets`.

```yaml
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/download-artifact@v4
        with:
          name: dist
      - run: ./deploy.sh
        env:
          DEPLOY_TOKEN: ${{ secrets.DEPLOY_TOKEN }}
```

- Secrets sind nur für den Deploy gedacht und gelangen nie in das Frontend-Bundle.
- Rollback: vorheriges Artefakt oder Image-Tag erneut ausrollen (`git revert` und Pipeline, oder Rollback-Funktion des Hosters).
- Images mit Commit-SHA taggen (nicht nur `latest`), damit jede Version eindeutig zurückgeholt werden kann.
