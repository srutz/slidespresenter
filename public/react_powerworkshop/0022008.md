
# 22.8 SemVer und npm (Zusatzthema) / package.json als Vertrag

## Die package.json Datei

- `package.json` ist die zentrale Manifest-Datei eines npm-Projekts. Sie beschreibt unter anderem:
  - Name und eigene Version des Pakets (`name`, `version`)
  - Skripte (`scripts`), z. B. `npm run dev`, `npm run build`
  - Abhängigkeiten in verschiedenen Kategorien

```json
{
  "name": "meine-app",
  "version": "1.4.2",
  "dependencies": { "react": "^19.0.0" },
  "devDependencies": { "vite": "^6.0.0" },
  "peerDependencies": { "react": ">=18" },
  "optionalDependencies": { "fsevents": "^2.3.0" }
}
```

## Die vier Arten von Abhängigkeiten

- **dependencies**: wird zur Laufzeit benötigt und mit ausgeliefert (z. B. `react`).
- **devDependencies**: wird nur während der Entwicklung/des Builds benötigt (z. B. `vite`, `eslint`, Testwerkzeuge).
- **peerDependencies**: signalisiert "diese Version musst *du* (der Nutzer des Pakets) selbst bereitstellen" - typisch für Plugins/Libraries, die zu einer bestimmten Version von React o. Ä. passen müssen.
- **optionalDependencies**: darf fehlschlagen, ohne dass die Installation abbricht (z. B. plattformspezifische Pakete).

- `package.json` ist damit ein **Vertrag**: Er legt fest, welche Versionsbereiche als kompatibel gelten - die konkrete Umsetzung übernimmt npm.
