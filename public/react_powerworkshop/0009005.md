# 9.5 HTTP, APIs und Server State / Loading-, Error- und Empty-States

## Jede Datenabfrage hat mehrere Zustände

- Eine Abfrage ist nie nur "Daten da": die UI muss mindestens vier Fälle behandeln
  - **Loading**: die Antwort steht noch aus
  - **Error**: Netzwerkfehler oder Fehlerstatus (`!response.ok`)
  - **Empty**: die Abfrage war erfolgreich, liefert aber eine leere Liste
  - **Success**: Daten sind vorhanden
- Drei getrennte Booleans (`isLoading`, `hasError`, `data`) erlauben unmögliche Kombinationen, z. B. "lädt" und "Fehler" gleichzeitig.
- Besser: ein einziger Zustand als **Discriminated Union**, bei dem TypeScript pro Fall die erlaubten Felder kennt.

# 9.5 HTTP, APIs und Server State / Request-State als Discriminated Union

## Typ für den Request-State

```typescript
type Todo = { id: number; todo: string; completed: boolean }

type RequestState<T> =
    | { status: 'loading' }
    | { status: 'error'; error: string }
    | { status: 'success'; data: T }

const initial: RequestState<Todo[]> = { status: 'loading' }
```

- Das Feld `status` ist der Diskriminator.
- Nur im Fall `success` existiert `data`, nur im Fall `error` existiert `error`.
- Der Zugriff auf `state.data` ohne vorherige Prüfung ist ein Compile-Fehler.
- "Empty" ist kein eigener Status, sondern ein Sonderfall von `success` (`data.length === 0`).

# 9.5 HTTP, APIs und Server State / Loading-, Error- und Empty-States

## Beispiel mit fetch

```typescript
import { useEffect, useState } from 'react'

export function TodoList() {
    const [state, setState] = useState<RequestState<Todo[]>>({ status: 'loading' })

    useEffect(() => {
        fetch('https://dummyjson.com/todos?limit=10')
            .then(res => {
                if (!res.ok) throw new Error(`HTTP ${res.status}`)
                return res.json() as Promise<{ todos: Todo[] }>
            })
            .then(json => setState({ status: 'success', data: json.todos }))
            .catch(e => setState({ status: 'error', error: String(e) }))
    }, [])

    if (state.status === 'loading') return <p>Laden…</p>
    if (state.status === 'error') return <p role="alert">Fehler: {state.error}</p>
    if (state.data.length === 0) return <p>Keine Todos vorhanden.</p>

    return <ul>{state.data.map(t => <li key={t.id}>{t.todo}</li>)}</ul>
}
```

- Early Returns halten den Success-Fall übersichtlich; nach den Prüfungen ist `state` auf `success` eingeengt (Narrowing).
