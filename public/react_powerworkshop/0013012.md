# 13.12 Testing / Tests in CI/CD

## GitHub Actions: Unit- und Komponententests

- Die Pipeline läuft bei jedem Push und Pull Request; schnelle Prüfungen zuerst.
- `npm ci` installiert reproduzierbar aus der `package-lock.json`; `cache: npm` cached den npm-Cache.

```yaml
# .github/workflows/ci.yml
name: CI
on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run lint
      - run: npx tsc --noEmit
      - run: npx vitest run
```

# 13.12 Testing / Tests in CI/CD: Playwright

- Browser werden separat installiert, `--with-deps` installiert zusätzlich Systembibliotheken.
- Der Report wird immer (`if: ${{ !cancelled() }}`) als Artefakt hochgeladen, um Fehler nachvollziehen zu können.

```yaml
  e2e:
    runs-on: ubuntu-latest
    needs: test
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npx playwright test
      - uses: actions/upload-artifact@v4
        if: ${{ !cancelled() }}
        with:
          name: playwright-report
          path: playwright-report/
          retention-days: 14
```

# 13.12 Testing / Tests in CI/CD: Empfehlungen

- Vitest erkennt CI automatisch; `vitest run` beendet sich nach einem Durchlauf (kein Watch-Modus).
- In `playwright.config.ts`: `retries: process.env.CI ? 2 : 0` und `workers: 1` bei knappen Ressourcen.
- Der Trace aus `trace: 'on-first-retry'` landet im Report und erleichtert die Analyse fehlgeschlagener Läufe.
- Coverage (`vitest run --coverage`) als Information, nicht als starres Gate.
- Branch Protection: Merge in `main` nur bei grüner Pipeline.
- Jobs parallelisieren (lint, unit, e2e), um die Wartezeit kurz zu halten.
