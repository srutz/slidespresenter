# 7.11 Hooks und moderne React Patterns / Optimierung der Performance mit "useMemo()", "React.memo()" und "useCallback()"

- Die 3 "Performance-Optimierungen" von React sind:
    1. `useMemo()`
    2. `useCallback()`
    3. `React.memo()`

- `useMemo()` und `useCallback()` sind Hooks, die es ermöglichen, Werte und Funktionen zu speichern, um unnötige Berechnungen zu vermeiden.
- `React.memo()` ist eine Higher-Order-Component, die es ermöglicht, Komponenten zu speichern, um unnötige Renderings zu vermeiden.

- Diese 3 Optimierungen sind REINE Optimierungen und verbessern "nur" potentiell die Performance.
- Der neue React-Compiler optimiert den Code und macht diese Optimierungen überflüssig.



# 7.11 Hooks und moderne React Patterns / Optimierung der Performance mit "useMemo()"

- Achtung: `useMemo` sollte nur verwendet werden, wenn es wirklich notwendig ist, da es die Lesbarkeit des Codes beeinträchtigen kann und außerdem sich die Performance nicht immer verbessert.

- Achtung2: `useMemo` bedeutet, dass der Wert nur berechnet wird, wenn sich die Werte in der Abhängigkeitsliste ändern. Das bedeutet, dass der Wert nicht bei jedem Rendern neu berechnet wird. Dafür muss man aber darauf achten, dass die Abhängigkeitsliste korrekt ist.

```typescript
import { useMemo, useState } from 'react'

export function Counter() {
    const [count, setCount] = useState(0)
    const isEven = useMemo(() => count % 2 === 0, [count])
    return (
        <div>
            <button onClick={() => setCount(count + 1)}>Increment</button>
            <p>{count}</p>
            <p>{isEven ? 'Even' : 'Odd'}</p>
        </div>
    )
}
```

# 7.11 Hooks und moderne React Patterns / Optimierung der Performance mit "useCallback()"

- `useCallback` ist ein Hook, der es ermöglicht, Funktionen zu speichern, damit diese beim Rerendern nicht neu erstellt werden müssen. 

```typescript
import { useCallback, useState } from 'react'

export function Counter() {
    const [count, setCount] = useState(0)
    const increment = useCallback(() => setCount(count + 1), [count])
    return (
        <div>
            <button onClick={increment}>Increment</button>
            <p>{count}</p>
        </div>
    )
}
```

# 7.11 Hooks und moderne React Patterns / Optimierung der Performance mit "React.memo()"

- `React.memo` ist eine Higher-Order-Component, die es ermöglicht, Komponenten zu speichern, um unnötige Renderings zu vermeiden. 

```typescript
import React, { useState } from 'react'
import { BigText } from './BigText'
import { UserPicture } from './UserPicture'
import { UserPictureWithLink } from './UserPictureWithLink'
import { LinkRenderer } from './LinkRenderer'

export const UserPictureWithLinkMemo = React.memo(UserPictureWithLink)

export function App() {
    const [count, setCount] = useState(0)
    return (
        <div>
            <button onClick={() => setCount(count + 1)}>Increment</button>
            <p>{count}</p>
            <UserPictureWithLinkMemo user={{ name: 'John Doe' }} />
        </div>
    )
}
```

# 7.11 Hooks und moderne React Patterns / Overuse von useMemo() und useCallback()

- `useMemo` und `useCallback` sind Hooks, die es ermöglichen, Werte und Funktionen zu speichern, um unnötige Berechnungen zu vermeiden.
- Die eigentliche "Gefahr" besteht darin, dass es zu sogenannten Stale-References kommen kann, wenn die Abhängigkeitsliste nicht korrekt ist. Die Funktion wird dann nicht mehr aktualisiert und die Lambda-Capture wird nicht mehr aktualisiert.
- Das bedeutet, dass die Funktion nicht mehr auf den aktuellen Zustand zugreift, sondern auf den Zustand, der zum Zeitpunkt der Erstellung der Funktion gültig war.


# 7.11 Hooks und moderne React Patterns / Overuse von useMemo() und useCallback()

Nichtsdestotrotz gibt es Fälle in denen `useMemo` und `useCallback` eingesetzt werden müssen (wenn man nicht den neuen React-Compiler verwendet):

1. Wenn eine Funktion als Prop an eine Child-Komponente übergeben wird, die mit `React.memo` optimiert ist.
2. Wenn eine Funktion in einer Abhängigkeitsliste eines anderen Hooks verwendet wird (z.B. `useEffect`, `useMemo`, `useCallback`).


Beispiel:

```typescript
import { useCallback, useState } from 'react'
import { ChildComponent } from './ChildComponent'       

export function MyComponent() {
    const [count, setCount] = useState(0)
    const increment = useCallback(() => setCount(count + 1), [count])
    return (
        <div>
            <button onClick={increment}>Increment</button>
            <p>{count}</p>
            <ChildComponent onClick={increment} />
        </div>
    )
}
```

Ohne useCallback würde die Funktion `increment` bei jedem Rendern neu erstellt werden, was dazu führen würde, dass `ChildComponent` bei jedem Rendern neu gerendert wird, auch wenn sich die Props nicht logisch(!) geändert haben. Falls ChildComponent mit React.memo optimiert ist, würde dies den Zweck der Optimierung zunichte machen. Ohne memo() würde ChildComponent bei jedem Rendern neu gerendert werden, auch wenn sich die Props nicht geändert haben.



# 7.11 Hooks und moderne React Patterns / useReducer() als Alternative zu useState()

## useReducer

- useReducer ist eine Alternative zu useState, wenn der Zustand komplexer wird.
- useReducer akzeptiert einen Reducer und einen initialen Zustand.
- Die Verwendung von useReducer ist ähnlich wie bei Redux.
- useReducer ist Geschmackssache und kann in vielen Fällen durch useState ersetzt werden.
- useReducer löst neben useState auch Re-Rendering aus und bringt Reactivity mit sich.

# 7.11 Hooks und moderne React Patterns / useReducer() als Alternative zu useState()

## useReducer Beispiel

```typescript
const initialState = { count: 0 }

function reducer(state, action) {
    switch (action.type) {
        case 'increment':
            return { count: state.count + 1 };
        case 'decrement':
            return { count: state.count - 1 };
        default:
            throw new Error();
    }
}
```

# useReducer Pitfalls

- Beim Reducer ist darauf zu achten, dass der neue Zustand immer neu erstellt wird. 
- Außerdem müssen die Operationen im Reducer immer rein sein und keine Seiteneffekte haben. Dies bedeutet, dass eine mehrfache Ausführung des Reducers immer das gleiche Ergebnis liefern muss. Diese Eigenschaft wird auch als "Pure Function" oder als Idempotenz bezeichnet.
- Der Reducer sollte auch keine Seiteneffekte haben. Das bedeutet, dass der Reducer keine Netzwerkanfragen oder Ähnliches ausführen sollte. Lediglich der Zustand sollte verändert werden.

- Generell bleibt anzumerken, dass die Verwendung von useReducer in React-Anwendungen eher selten ist. In der Regel reicht useState aus. useReducer ist deutlich schwieriger zu verstehen und zu verwenden.
