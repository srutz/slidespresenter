# 6.1 React mit TypeScript / TypeScript von Beginn an

## Warum TypeScript von Anfang an

- Typfehler werden im Editor sofort angezeigt, nicht erst zur Laufzeit im Browser.
- Props, State und Events sind dokumentiert und per Autovervollständigung auffindbar.
- Refactorings (Umbenennen, Props ändern) sind sicher.
- Moderne Bibliotheken (TanStack Query, Zustand, React Hook Form, Zod) bringen eigene Typen mit und sind auf TypeScript ausgelegt.
- Nachträgliches Migrieren eines JavaScript-Projekts ist aufwendiger als der Start mit TypeScript.

# 6.1 React mit TypeScript / TypeScript von Beginn an

## Projekt mit Vite anlegen

```bash
npm create vite@latest my-app -- --template react-ts
cd my-app
npm install
npm run dev
```

- Dateiendungen: .ts für reinen Code, .tsx für Dateien mit JSX.
- Vite transpiliert TypeScript nur (ohne Typprüfung). Die Typprüfung passiert im Editor und per `tsc -b` (Teil von `npm run build`).

## tsconfig Grundlagen

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noEmit": true,
    "skipLibCheck": true
  },
  "include": ["src"]
}
```

- strict: true aktiviert u. a. strictNullChecks und noImplicitAny. Immer eingeschaltet lassen.
- jsx: react-jsx macht den Import von React in jeder Datei überflüssig.
- Das Vite-Template teilt die Konfiguration auf mehrere Dateien auf (tsconfig.app.json, tsconfig.node.json).
