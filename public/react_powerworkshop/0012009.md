# 12.9 State Management mit Zustand / Zustand: Strukturierung größerer Stores

## Mehrere kleine Stores

- Zustand empfiehlt keinen einzelnen Riesen-Store wie bei Redux: mehrere Stores nach Fachlichkeit sind völlig in Ordnung.
- Jeder Store ist ein eigener Hook, ohne Provider und unabhängig testbar.

```typescript
// stores/useCartStore.ts, stores/useUiStore.ts, stores/useFilterStore.ts
export const useUiStore = create<UiStore>()((set) => ({
    sidebarOpen: false,
    toggleSidebar: () => set((s) => ({ sidebarOpen: !s.sidebarOpen })),
}))
```

- Ein Store, wenn sich State und Actions gegenseitig brauchen. Mehrere Stores, wenn die Bereiche unabhängig sind.
- Kein Store pro Komponente: lokaler State bleibt `useState`.

# 12.9 State Management mit Zustand / Zustand: Strukturierung größerer Stores

## Slices Pattern mit StateCreator

- Ein großer Store wird in **Slices** zerlegt, die jeweils mit `StateCreator` typisiert sind und zu einem Store kombiniert werden.
- Die Typargumente: gesamter Store, Middleware-Mutatoren (hier leer), Middleware der Slice, Slice-Typ.

```typescript
import { create, type StateCreator } from 'zustand'

type Todo = { id: number; text: string; done: boolean }

type TodoSlice = {
    todos: Todo[]
    addTodo: (text: string) => void
}
type FilterSlice = {
    filter: 'all' | 'open' | 'done'
    setFilter: (f: FilterSlice['filter']) => void
}
type AppStore = TodoSlice & FilterSlice

const createTodoSlice: StateCreator<AppStore, [], [], TodoSlice> = (set) => ({
    todos: [],
    addTodo: (text) =>
        set((s) => ({ todos: [...s.todos, { id: Date.now(), text, done: false }] })),
})

const createFilterSlice: StateCreator<AppStore, [], [], FilterSlice> = (set) => ({
    filter: 'all',
    setFilter: (filter) => set({ filter }),
})
```

## Slices kombinieren

```typescript
export const useAppStore = create<AppStore>()((...args) => ({
    ...createTodoSlice(...args),
    ...createFilterSlice(...args),
}))
```

- Slices können über `get()` auf andere Slices zugreifen, da der Typ `AppStore` ist.
- Mit Middleware: `StateCreator<AppStore, [['zustand/immer', never]], [], TodoSlice>`. Die Middleware wird nur auf den kombinierten Store angewendet, nicht auf einzelne Slices.
- Dateien: eine Datei pro Slice (`todoSlice.ts`, `filterSlice.ts`), eine `store.ts` zum Zusammenbauen.

## Actions bündeln und Testbarkeit

- Actions in einem eigenen Namespace `actions` trennt Daten und Verhalten. So braucht ein Selektor nie `useShallow` für Actions.
- Tests setzen den Store direkt zurück und prüfen mit `getState()`, ohne React.

```typescript
export const useTodoStore = create<TodoStore>()((set) => ({
    todos: [],
    actions: {
        addTodo: (text) => set((s) => ({ todos: [...s.todos, { id: Date.now(), text, done: false }] })),
        clear: () => set({ todos: [] }),
    },
}))

export const useTodoActions = () => useTodoStore((s) => s.actions)
```

```typescript
import { beforeEach, expect, test } from 'vitest'

beforeEach(() => useTodoStore.setState({ todos: [] }))

test('addTodo fügt ein Todo hinzu', () => {
    useTodoStore.getState().actions.addTodo('Lernen')
    expect(useTodoStore.getState().todos).toHaveLength(1)
})
```
