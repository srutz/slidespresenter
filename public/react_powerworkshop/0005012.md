# 5.12 React-Komponenten im Detail / React Compiler und automatische Optimierungen

## Was der React Compiler macht

- Der React Compiler (Version 1.0, stabil seit Oktober 2025) ist ein Build-Zeit-Tool.
- Er analysiert Komponenten und Hooks und fügt automatisch Memoization ein, entsprechend memo, useMemo und useCallback.
- Ergebnis: weniger unnötige Re-Renderings ohne manuellen Code.
- Funktioniert auch bei Stellen, an denen useMemo nicht möglich ist (z. B. nach einem frühen return).
- Voraussetzung: Der Code hält die Rules of React ein (reine Render-Funktionen, kein Mutieren von Props/State, Rules of Hooks).
- Nicht regelkonforme Komponenten werden übersprungen, statt kaputt optimiert zu werden.

# 5.12 React-Komponenten im Detail / React Compiler und automatische Optimierungen

## Aktivierung in Vite

```bash
npm install -D babel-plugin-react-compiler
```

```typescript
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
    plugins: [
        react({
            babel: {
                plugins: ['babel-plugin-react-compiler'],
            },
        }),
    ],
})
```

- Je nach Version des Vite-Templates kann die Aktivierung bereits per Option beim Anlegen des Projekts erfolgen. Die Plugin-Konfiguration ist dann etwas anders (siehe Dokumentation).

## ESLint und Praxis

- eslint-plugin-react-hooks (ab Version 6, Preset recommended) enthält Regeln des Compilers und meldet Verstöße gegen die Rules of React.
- Im React DevTools sind kompilierte Komponenten mit "Memo" markiert.
- Schrittweise Einführung ist möglich (z. B. nur einzelne Verzeichnisse oder per "use memo"-Direktive bzw. "use no memo" zum Ausschluss).

## Wann memo, useMemo und useCallback trotzdem sinnvoll sind

- Als Escape Hatch, wenn eine Funktion oder ein Wert als Abhängigkeit eines Effects stabil bleiben muss.
- Bei nachweislich teuren Berechnungen, die der Compiler nicht abdeckt (Messen im Profiler).
- Bestehender Code mit memo muss nicht entfernt werden.
- Neuer Code: zuerst ohne manuelle Optimierung schreiben.
