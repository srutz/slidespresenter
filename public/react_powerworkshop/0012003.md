# 12.3 State Management mit Zustand / useState, Context oder globaler Store?

## Drei Stufen

- **`useState`**: State wird in einer Komponente benutzt, bei Bedarf per Props an Kinder gereicht. Der Standard.
- **Lifting State Up + Context**: mehrere weit entfernte Komponenten brauchen denselben, selten geänderten Wert (Theme, Sprache, aktueller Benutzer).
- **Globaler Store (Zustand)**: viele Komponenten lesen und schreiben häufig geänderten Client-State, oder die Logik soll außerhalb von React testbar sein.

```typescript
// Stufe 1: lokal
const [open, setOpen] = useState(false)

// Stufe 2: Context für selten wechselnde Werte
const ThemeContext = createContext<'light' | 'dark'>('light')
const theme = use(ThemeContext)

// Stufe 3: Store mit Selektor
const count = useCounterStore((s) => s.count)
```

# 12.3 State Management mit Zustand / useState, Context oder globaler Store?

## Das Re-Render-Problem von Context

- Ändert sich der `value` eines Providers, rendern **alle** Consumer neu, auch wenn sie nur einen Teil des Werts nutzen.
- Context kennt keine Selektoren: ein Consumer kann nicht "nur `todos`" abonnieren.
- Ein neues Objekt im `value` (`value={{ todos, add }}`) löst bei jedem Render des Providers Updates aus, sofern es nicht memoisiert ist.

```typescript
const TodoContext = createContext<{ todos: Todo[]; filter: string } | null>(null)

// Jeder Consumer rendert bei JEDER Änderung von todos ODER filter neu
function FilterLabel() {
    const ctx = use(TodoContext)
    return <span>{ctx?.filter}</span>
}
```

- Abhilfe mit Context: mehrere kleine Contexts aufteilen oder memoisieren, wird aber schnell aufwendig.

# 12.3 State Management mit Zustand / useState, Context oder globaler Store?

## Entscheidungshilfe

- Brauchen nur Komponente und Kinder den Wert? **`useState`**.
- Ist es ein selten geänderter Wert für einen ganzen Teilbaum (Theme, Locale, Auth)? **Context**.
- Ändert sich der Wert häufig und lesen ihn viele Komponenten unabhängig voneinander? **Zustand**.
- Sind es Daten vom Server? **TanStack Query**, kein Store.
- Soll der Zustand per Link teilbar sein? **URL**.
- Zustand braucht keinen Provider und rendert nur Komponenten neu, deren Selektor sich geändert hat.
- Außerhalb von React erreichbar: `useStore.getState()` und `useStore.setState()`, z. B. in Tests oder Event-Handlern.
