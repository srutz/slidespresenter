# 6.7 React mit TypeScript / Union Types und Discriminated Unions

## Union Types und Literal Types

- Ein Union Type beschreibt einen Wert, der einer von mehreren Typen sein kann.
- Literal Types schränken auf konkrete Werte ein. Sie ersetzen oft enum.

```typescript
type Size = 'sm' | 'md' | 'lg'
type Id = string | number

type ButtonProps = {
    size?: Size
    variant: 'primary' | 'secondary' | 'danger'
    children: React.ReactNode
}

function Button({ size = 'md', variant, children }: ButtonProps) {
    return <button className={`btn btn-${variant} btn-${size}`}>{children}</button>
}

<Button variant="primary">OK</Button>
// <Button variant="blue">  -> Compilerfehler
```

# 6.7 React mit TypeScript / Union Types und Discriminated Unions

## Discriminated Unions für Request-State

- Gemeinsames Feld (Discriminator) mit Literal-Typ: TypeScript kennt nach der Prüfung genau die passende Variante.
- Unmögliche Zustände (loading und data gleichzeitig) sind nicht darstellbar.

```typescript
type RequestState<T> =
    | { status: 'loading' }
    | { status: 'error'; error: Error }
    | { status: 'success'; data: T }

function UserList({ state }: { state: RequestState<User[]> }) {
    if (state.status === 'loading') return <p>Lade ...</p>
    if (state.status === 'error') return <p>{state.error.message}</p>
    return <ul>{state.data.map(u => <li key={u.id}>{u.name}</li>)}</ul>
}
```

## Exhaustive switch mit never

- Wird eine Variante vergessen, meldet der Compiler einen Fehler.

```typescript
function assertNever(x: never): never {
    throw new Error(`Unerwarteter Wert: ${JSON.stringify(x)}`)
}

function render(state: RequestState<User[]>) {
    switch (state.status) {
        case 'loading': return <p>Lade ...</p>
        case 'error': return <p>{state.error.message}</p>
        case 'success': return <p>{state.data.length} Benutzer</p>
        default: return assertNever(state)
    }
}
```

- Fügt man später den Status 'idle' hinzu, markiert TypeScript alle switch-Stellen, die ihn noch nicht behandeln.
- Dieselbe Technik eignet sich für Actions in useReducer.
