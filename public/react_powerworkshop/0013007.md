# 13.7 Testing / React Testing Library: Komponenten aus Sicht des Benutzers testen

## render, screen und Queries

- `render()` mountet die Komponente in ein jsdom-Dokument, `screen` bietet die Queries.
- Queries nach Priorität: `getByRole` (mit `name`), `getByLabelText`, `getByText`, erst zuletzt `getByTestId`.
- `getBy` wirft einen Fehler, wenn nichts gefunden wird, `queryBy` liefert `null` (für "nicht vorhanden"), `findBy` wartet asynchron.

```typescript
import { render, screen } from '@testing-library/react'
import { LoginForm } from './LoginForm'

test('renders form fields', () => {
  render(<LoginForm onSubmit={() => {}} />)

  expect(screen.getByRole('heading', { name: /anmelden/i })).toBeInTheDocument()
  expect(screen.getByLabelText(/e-mail/i)).toBeInTheDocument()
  expect(screen.queryByText(/fehler/i)).not.toBeInTheDocument()
})
```

# 13.7 Testing / React Testing Library: Interaktion mit userEvent

- `userEvent.setup()` simuliert echte Benutzer: Fokus, Tastendrücke, Klicks in der richtigen Reihenfolge.
- Alle `userEvent`-Aufrufe sind asynchron und müssen mit `await` aufgerufen werden.
- RTL 16 benötigt `@testing-library/dom` als Peer-Dependency.

```typescript
import userEvent from '@testing-library/user-event'

test('submits entered values', async () => {
  const user = userEvent.setup()
  const onSubmit = vi.fn()
  render(<LoginForm onSubmit={onSubmit} />)

  await user.type(screen.getByLabelText(/e-mail/i), 'anna@example.com')
  await user.click(screen.getByRole('button', { name: /anmelden/i }))

  expect(onSubmit).toHaveBeenCalledWith({ email: 'anna@example.com' })
})
```

# 13.7 Testing / React Testing Library: Asynchronität und Matcher

- `findBy...` wartet (Standard 1000 ms) bis das Element erscheint, `waitFor` wiederholt eine Prüfung.
- jest-dom liefert lesbare Matcher: `toBeInTheDocument`, `toBeDisabled`, `toHaveValue`, `toHaveTextContent`, `toBeVisible`.
- Setup einmalig in `src/testsetup.ts`: `import '@testing-library/jest-dom/vitest'`.

```typescript
test('shows greeting after loading', async () => {
  render(<UserGreeting userId="1" />)

  expect(screen.getByText(/lädt/i)).toBeInTheDocument()
  expect(await screen.findByText(/hallo anna/i)).toBeInTheDocument()
  expect(screen.getByRole('button', { name: /abmelden/i })).toBeEnabled()
})
```

# 13.7 Testing / React Testing Library: Anti-Pattern

- Nicht testen: interner State, Methodennamen, CSS-Klassen, Anzahl der Renders, Komponentenstruktur.
- Nicht verwenden: `container.querySelector`, `getByTestId` als Standard, Snapshots großer Bäume.
- Nicht tun: feste Wartezeiten (`setTimeout`) oder `act()` manuell um RTL-Aufrufe wickeln.
- Faustregel: Ändert sich nur die Implementierung, aber nicht das sichtbare Verhalten, darf kein Test rot werden.
- Hilfreich: `screen.logTestingPlaygroundURL()` und `screen.debug()` zeigen passende Queries.
