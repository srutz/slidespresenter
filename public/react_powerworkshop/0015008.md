# 15.8 Best Practices und Architektur / Performance

## Erst messen, dann optimieren

- React DevTools Profiler und Browser-Performance-Tab zeigen echte Engpässe; nicht raten.
- Der React Compiler (Kapitel 5) übernimmt viel Memoization; `useMemo`/`useCallback` nur bei gemessenem Bedarf.
- Listen: stabile `key`-Werte (IDs), bei sehr langen Listen Virtualisierung (z. B. TanStack Virtual) oder Paginierung.
- Code Splitting: Routen per `lazy()` und `Suspense` laden (Kapitel 10, 14).
- Daten: Caching und `staleTime` in TanStack Query nutzen, unnötige Requests vermeiden.
- Bundle-Größe mit Vite-Build-Analyse prüfen; schwere Bibliotheken nur dort importieren, wo sie gebraucht werden.
- Bilder in passender Größe und mit `loading="lazy"` laden.

# 15.8 Best Practices und Architektur / Security-Grundlagen

- XSS: React escaped Ausgaben automatisch; `dangerouslySetInnerHTML` nur mit sanitisiertem HTML (z. B. DOMPurify).
- Benutzereingaben in `href`/`src` prüfen (`javascript:`-URLs).
- Tokens: Session-Cookies mit `HttpOnly`, `Secure`, `SameSite` sind sicherer als Tokens im `localStorage`, das bei XSS auslesbar ist.
- Content Security Policy (CSP) als zweite Schutzschicht per HTTP-Header.
- Abhängigkeiten: `npm audit` regelmäßig, Lockfile einchecken, Updates automatisieren (Dependabot/Renovate).
- Keine Secrets im Bundle: alles mit `VITE_` im Präfix landet im Browser und ist öffentlich (Kapitel 14).
- Validierung im Client dient der Bedienung; Sicherheit entscheidet immer der Server.

```typescript
// schlecht: Rohes HTML aus Nutzerdaten
<div dangerouslySetInnerHTML={{ __html: comment.html }} />
// besser: als Text ausgeben
<p>{comment.text}</p>
```
