# 14.6 Build, Deployment und Produktion / Deployment mit Nginx und Docker

## Multi-Stage Dockerfile

- Stage 1 baut die App mit Node, Stage 2 enthält nur nginx und `dist/`: kleines Image ohne Node und Quellcode.

```bash
# Dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
```

- `package*.json` wird zuerst kopiert, damit der Layer mit `npm ci` gecacht wird, solange sich die Abhängigkeiten nicht ändern.
- Eine `.dockerignore` mit `node_modules`, `dist` und `.git` hält den Build-Kontext klein.

# 14.6 Build, Deployment und Produktion / nginx.conf

```bash
server {
  listen 80;
  root /usr/share/nginx/html;
  index index.html;

  # Hash-Dateien: langes Caching
  location /assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
  }

  # Reverse-Proxy zum Backend
  location /api/ {
    proxy_pass http://backend:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }

  # SPA-Fallback
  location / {
    try_files $uri /index.html;
    add_header Cache-Control "no-cache";
  }
}
```

- Der Proxy auf `/api` vermeidet CORS-Probleme: Browser und API haben denselben Origin.

# 14.6 Build, Deployment und Produktion / Image bauen und starten

```bash
docker build -t my-react-app .
docker run -d -p 8080:80 --name my-react-app my-react-app
# App unter http://localhost:8080
```

- Mit Docker Compose zusammen mit dem Backend, der Name `backend` wird zum Host im Proxy:

```bash
# compose.yaml
services:
  web:
    build: .
    ports:
      - "8080:80"
    depends_on:
      - backend
  backend:
    image: my-backend:latest
```

- Das Image enthält nur statische Dateien: Start in Millisekunden, einfach zu skalieren.
- Weitere Härtung: `nginx-unprivileged`, gzip/brotli, Security-Header (CSP, `X-Content-Type-Options`), HTTPS am Load Balancer.
