# 14.5 Build, Deployment und Produktion / SPA-Hosting und Server-Fallback

## Warum Deep-Links 404 liefern

- Eine SPA besteht aus einer `index.html`; Routen wie `/users/42` existieren nur im Client-Router.
- Beim Klick im Browser funktioniert die Navigation, beim Reload oder Aufruf eines Links fragt der Browser den Server nach `/users/42`.
- Der Server findet keine Datei und antwortet mit 404.
- Lösung: Fallback-Regel, die alle Pfade ohne passende Datei auf `/index.html` umleitet (Status 200).
- Echte Fehlerseiten ("Seite nicht gefunden") rendert danach der Router mit einer Catch-all-Route.

```bash
# Prinzip bei nginx
try_files $uri /index.html;
```

- `vite preview` und `vite dev` machen diesen Fallback bereits selbst; deshalb fällt das Problem erst im Deployment auf.

# 14.5 Build, Deployment und Produktion / Caching-Header

- Dateien in `assets/` haben einen Hash im Namen: dürfen ewig gecacht werden.
- `index.html` verweist auf die aktuellen Hash-Dateien: darf nicht gecacht werden, sonst sehen Benutzer alte Versionen.

```bash
# Dateien mit Hash im Namen
Cache-Control: public, max-age=31536000, immutable

# index.html
Cache-Control: no-cache
```

- `no-cache` bedeutet: Browser darf speichern, muss aber bei jedem Abruf beim Server nachfragen (ETag, 304).
- Nach einem Deployment fordern Browser mit geöffneter alter Seite eventuell Chunks an, die nicht mehr existieren: Fehler beim Lazy Loading abfangen (Error Boundary, Reload anbieten) oder alte Dateien einige Zeit behalten.

# 14.5 Build, Deployment und Produktion / base-Pfad in Vite

- Läuft die App nicht unter `/`, sondern in einem Unterpfad (z.B. `https://example.com/shop/` oder GitHub Pages `/repo-name/`), muss der Pfad beim Build bekannt sein.

```typescript
// vite.config.ts
export default defineConfig({
  base: '/shop/',
})
```

- Vite schreibt dann alle Asset-URLs in `index.html` mit diesem Präfix.
- Der Router braucht denselben Basis-Pfad:

```typescript
const router = createBrowserRouter(routes, {
  basename: import.meta.env.BASE_URL,
})
```

- Statische Dateien aus `public/` im Code mit `import.meta.env.BASE_URL + 'logo.svg'` referenzieren.
