# 4.5 Styling mit Tailwind CSS / States und Varianten

## Varianten-Präfixe

- Mit einem Präfix gilt eine Utility-Klasse nur in einem bestimmten Zustand
- Pseudo-Klassen: `hover:`, `focus:`, `active:`, `disabled:`, `focus-visible:`, `first:`, `last:`, `odd:`, `even:`
- Formulare: `placeholder:`, `invalid:`, `checked:`, `required:`
- Varianten lassen sich kombinieren: `md:hover:bg-blue-700`, `dark:disabled:opacity-40`
- `focus-visible:` zeigt den Fokusring nur bei Tastaturbedienung, wichtig für Barrierefreiheit
- In Tailwind 4 gilt `hover:` nur auf Geräten, die tatsächlich Hover unterstützen (nicht bei Touch)

## Beispiel: Button mit States

```typescript
export function SaveButton({ disabled }: { disabled?: boolean }) {
  return (
    <button
      disabled={disabled}
      className="rounded-lg bg-blue-600 px-4 py-2 font-medium text-white
        transition-colors
        hover:bg-blue-700
        active:bg-blue-800
        focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-blue-600
        disabled:cursor-not-allowed disabled:opacity-50"
    >
      Speichern
    </button>
  )
}
```

## group, peer, aria und data

- `group` am Elternelement, `group-hover:` an den Kindern:

```typescript
<a href="/details" className="group flex items-center gap-2">
  <span>Details</span>
  <span className="transition-transform group-hover:translate-x-1">-></span>
</a>
```

- `peer` am Geschwisterelement, `peer-checked:` oder `peer-invalid:` am nachfolgenden Element
- `aria-`Varianten reagieren auf ARIA-Attribute: `aria-disabled:opacity-50`, `aria-expanded:rotate-180`, `aria-[sort=ascending]:font-bold`
- `data-`Varianten reagieren auf Data-Attribute: `data-[state=open]:bg-slate-100`
- So bleibt der Zustand im Markup (und damit für Screenreader und Tests sichtbar), nicht nur in Klassen
