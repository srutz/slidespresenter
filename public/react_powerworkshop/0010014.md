# 10.14 Routing mit React Router / Data APIs: Loader und Actions

## Data Router

- Mit `createBrowserRouter` (Data Mode) können Routen zusätzlich Daten laden und Änderungen verarbeiten, **bevor** die Komponente rendert.
- `loader`: lädt Daten für die Route (GET), Zugriff in der Komponente mit `useLoaderData()`
- `action`: verarbeitet Änderungen (POST, PUT, DELETE) aus `<Form>` oder `useFetcher`
- `errorElement`: wird bei Fehlern in Loader, Action oder Rendering angezeigt
- Nach jeder Action lädt der Router die Loader der aktuellen Seite automatisch neu (Revalidation).

```typescript
import { createBrowserRouter, RouterProvider } from 'react-router'

const router = createBrowserRouter([
    {
        path: '/todos',
        Component: TodosPage,
        loader: todosLoader,
        action: todosAction,
        ErrorBoundary: TodosError,
    },
])

export function App() {
    return <RouterProvider router={router} />
}
```

## Loader

```typescript
import { useLoaderData, type LoaderFunctionArgs } from 'react-router'

type Todo = { id: number; todo: string; completed: boolean }

export async function todosLoader({ request }: LoaderFunctionArgs) {
    const q = new URL(request.url).searchParams.get('q') ?? ''
    const res = await fetch(`https://dummyjson.com/todos/search?q=${encodeURIComponent(q)}`, {
        signal: request.signal,   // Abbruch bei Navigation
    })
    if (!res.ok) throw new Response('Todos nicht ladbar', { status: res.status })
    const json: { todos: Todo[] } = await res.json()
    return json.todos
}

export function TodosPage() {
    const todos = useLoaderData() as Todo[]
    return <ul>{todos.map(t => <li key={t.id}>{t.todo}</li>)}</ul>
}
```

- Der Loader erhält `params` (URL-Parameter) und `request` (inkl. Search Params).
- Die Komponente rendert erst, wenn die Daten da sind, Loading-Zustände entfallen in der Komponente.
- Geworfene `Response`s und Errors landen im `ErrorBoundary`/`errorElement` der Route.

## Actions, Form und Pending UI

```typescript
import { Form, redirect, useNavigation, type ActionFunctionArgs } from 'react-router'

export async function todosAction({ request }: ActionFunctionArgs) {
    const formData = await request.formData()
    const todo = String(formData.get('todo'))
    await fetch('https://dummyjson.com/todos/add', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ todo, completed: false, userId: 1 }),
    })
    return redirect('/todos')
}

export function NewTodoForm() {
    const navigation = useNavigation()
    const busy = navigation.state === 'submitting'
    return (
        <Form method="post" action="/todos">
            <input name="todo" required />
            <button disabled={busy}>{busy ? 'Speichert…' : 'Anlegen'}</button>
        </Form>
    )
}
```

- `useNavigation().state` ist `'idle'`, `'loading'` oder `'submitting'`.
- `useFetcher()` löst Actions und Loader aus, ohne die URL zu wechseln (z. B. Abhaken in einer Liste).

## Einordnung gegenüber TanStack Query

- Loader und Actions laden und mutieren **pro Navigation**: einfach, URL-getrieben, kein Waterfall durch Komponenten.
- Sie haben keinen eigenen Cache mit `staleTime`, Hintergrund-Refetch bei Fokus oder optimistische Updates.
- TanStack Query ist besser bei häufig genutzten, geteilten oder langlebigen Daten.
- Beides lässt sich kombinieren: der Loader füllt den Cache vor (`queryClient.ensureQueryData`), die Komponente liest per `useQuery`.

```typescript
export const todosLoader = (queryClient: QueryClient) => async () =>
    queryClient.ensureQueryData({ queryKey: ['todos'], queryFn: fetchTodos })
```

- Faustregel: einfache Seiten und Formulare mit Router-Daten-APIs, komplexe Datenlogik mit TanStack Query.
