
# 22.3 SemVer und npm (Zusatzthema) / Vor-Versionen und Sonderfälle

## Pre-Release-Versionen

- Vor einem offiziellen Release können Vorabversionen mit einem Bindestrich-Suffix gekennzeichnet werden:

```
1.0.0-alpha
1.0.0-alpha.1
1.0.0-beta
1.0.0-rc.1
1.0.0
```

- Eine Pre-Release-Version gilt als **instabiler** als die zugehörige finale Version.
- Build-Metadaten können zusätzlich mit einem Plus-Zeichen angehängt werden, z. B. `1.0.0+20130313144700`. Sie beeinflussen den Versionsvergleich nicht und dienen nur der Information (z. B. Build-Nummer, Commit-Hash).

# 22.3 SemVer und npm (Zusatzthema) / Vor-Versionen und Sonderfälle

## Der Sonderfall 0.y.z

- Versionen mit MAJOR = `0` (also `0.y.z`) gelten als **initiale Entwicklungsphase**.
- In dieser Phase kann sich alles jederzeit ändern - es gibt noch keine stabile öffentliche Schnittstelle.
- Nutzer solcher Pakete sollten nicht davon ausgehen, dass `0.x` Versionen stabil oder abwärtskompatibel sind.
- Der Übergang zu `1.0.0` markiert den Zeitpunkt, ab dem sich die Autoren erstmals verbindlich an SemVer halten und eine stabile API zusichern.
