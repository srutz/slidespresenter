
# 23.1 Anhang: Styled Components / Überblick

## Was ist Styled Components?

- Eine **CSS-in-JS-Bibliothek**: CSS wird direkt neben der Komponente in TypeScript geschrieben.
- Statt Klassennamen zu verwalten, definiert man **Komponenten, die ihre Styles mitbringen**.
- Verbreitet seit ca. 2017, lange der De-facto-Standard für CSS-in-JS in React.
- Projektseite: [styled-components.com](https://styled-components.com)

```bash
npm install styled-components
```

# 23.2 Anhang: Styled Components / Grundprinzip

## Tagged Template Literals

- `styled.button` ist eine Funktion, die ein **Tagged Template Literal** entgegennimmt.
- Das Ergebnis ist eine ganz normale React-Komponente.

```typescript
import styled from 'styled-components'

const Button = styled.button`
  padding: 0.5rem 1rem;
  border-radius: 0.5rem;
  background: royalblue;
  color: white;
`

export function App() {
  return <Button onClick={() => alert('Hi')}>Klick</Button>
}
```

- Alle Props (`onClick`, `disabled`, ...) werden an das DOM-Element weitergereicht.

# 23.3 Anhang: Styled Components / Dynamische Styles

## Props und Theming

- Styles können Funktionen enthalten, die die Props der Komponente auslesen.
- **Transient Props** (Präfix `$`) werden nicht ans DOM weitergegeben.

```typescript
const Button = styled.button<{ $primary?: boolean }>`
  background: ${(p) => (p.$primary ? p.theme.colors.primary : 'lightgray')};
`

<ThemeProvider theme={{ colors: { primary: 'royalblue' } }}>
  <Button $primary>Speichern</Button>
</ThemeProvider>
```

- `ThemeProvider` stellt ein Theme per Context bereit.
- Erweiterung: `styled(Button)` erzeugt eine Variante einer bestehenden Komponente.
- Weitere Features: `css`-Helper, `keyframes`, `createGlobalStyle`, `.attrs()`, Selektoren wie `&:hover`.

# 23.4 Anhang: Styled Components / Wie es funktioniert

## Ablauf zur Laufzeit

1. Beim Rendern wird das Template mit den aktuellen Props **zu einem CSS-String ausgewertet**.
2. Aus dem String wird ein **Hash** berechnet, z.B. `sc-aBcDe`.
3. Die CSS-Regeln werden unter diesem generierten Klassennamen in ein `<style>`-Tag im `<head>` **eingefügt** (Stylesheet-Injection).
4. Die Klasse wird dem DOM-Element zugewiesen: `<button class="sc-aBcDe kXyZ">`.

- Ändern sich die Props, entsteht ein neuer String, ein neuer Hash und eine neue Klasse.
- Identische Styles teilen sich dieselbe Klasse (Caching).
- Die Klassennamen sind eindeutig, daher keine Kollisionen wie bei globalem CSS.
- Bei SSR sammelt `ServerStyleSheet` die Styles ein und fügt sie ins HTML ein.

# 23.5 Anhang: Styled Components / Vorteile

## Pros

- **Scoping**: Keine Klassenkollisionen, Styles gehören zur Komponente.
- **Co-Location**: Markup-Logik und Style an einem Ort, toter Code fällt leicht auf.
- **Dynamik**: Styles hängen direkt von Props und Theme ab, voller Zugriff auf TypeScript.
- **Theming** ist eingebaut.
- **Gute Developer Experience**: Echtes CSS inkl. Nesting, Pseudo-Klassen und Media Queries.
- **Reife**: Große Community, viele Beispiele, stabile API.

# 23.6 Anhang: Styled Components / Nachteile

## Cons

- **Laufzeitkosten**: CSS wird im Browser berechnet und injiziert. Das kostet CPU bei vielen dynamischen Komponenten.
- **Bundle-Größe**: Die Bibliothek selbst kommt zusätzlich ins Bundle (rund 12 kB gzip).
- **Server Components**: Es braucht Client-Kontext (React Context, `useInsertionEffect`). Integration in RSC und Streaming ist umständlich.
- **Kein Tooling-Vorteil**: Kein statisches Extrahieren, Stylelint und Syntax-Highlighting nur über Plugins.
- **Debugging**: Generierte Klassennamen sind schwer lesbar (ohne Babel/SWC-Plugin).
- **Verschiebung des Ökosystems**: Neue Projekte setzen vermehrt auf Alternativen (siehe nächste Folie).

# 23.7 Anhang: Styled Components / Aktueller Stand

## Momentum

- Styled Components ist weiterhin **sehr weit verbreitet**, vor allem durch Bestandsprojekte und Bibliotheken.
- Das Projekt befindet sich seit 2025 im **Maintenance-Modus**: Fehlerkorrekturen ja, neue Features kaum. Das Team rät bei Neuprojekten von der Nutzung ab.
- Auch die Konkurrenz Emotion wird kaum noch weiterentwickelt.
- Der Trend geht zu **Zero-Runtime-Ansätzen**, die das CSS zur Build-Zeit erzeugen:

| Ansatz | Beispiele |
|---|---|
| Utility-First | Tailwind CSS |
| Scoped CSS | CSS Modules |
| Zero-Runtime CSS-in-JS | vanilla-extract, Panda CSS, StyleX, Linaria |

- **Empfehlung**: Bestandsprojekte nicht hastig migrieren, im Neuprojekt (siehe Seminar-Stack) Tailwind oder CSS Modules wählen.
