# 7.20 Hooks und moderne React Patterns / Typische Hook-Anti-Patterns

## Hooks in Bedingungen und Schleifen

- Hooks müssen bei jedem Render in **derselben Reihenfolge** aufgerufen werden (Rules of Hooks, geprüft von `eslint-plugin-react-hooks`)

```typescript
// schlecht
function User({ id }: { id?: string }) {
    if (!id) return null
    const [user, setUser] = useState<User | null>(null)   // bedingter Hook
    ...
}

// gut: Hooks zuerst, Early Return danach
function User({ id }: { id?: string }) {
    const [user, setUser] = useState<User | null>(null)
    if (!id) return null
    ...
}
```

# 7.20 Hooks und moderne React Patterns / Fehlende oder gelogene Dependencies

```typescript
// schlecht: Dependency weggelassen, Linter-Warnung unterdrückt
useEffect(() => {
    fetchUser(userId).then(setUser)
    // eslint-disable-next-line react-hooks/exhaustive-deps
}, [])

// gut: alle verwendeten reaktiven Werte angeben
useEffect(() => {
    let cancelled = false
    fetchUser(userId).then(u => { if (!cancelled) setUser(u) })
    return () => { cancelled = true }
}, [userId])
```

- Die Dependency-Liste beschreibt, was der Effect liest, sie ist keine Steuerung "wann soll er laufen"
- Wird der Effect zu oft ausgelöst, den Code ändern, nicht die Liste
- Für Server-Daten besser TanStack Query statt eigener Effects

# 7.20 Hooks und moderne React Patterns / Abgeleiteter State und Effects für Datenfluss

```typescript
// schlecht: doppelter State, der synchronisiert werden muss
const [items, setItems] = useState<Item[]>([])
const [count, setCount] = useState(0)
useEffect(() => { setCount(items.length) }, [items])

// gut: beim Rendern berechnen
const [items, setItems] = useState<Item[]>([])
const count = items.length
```

```typescript
// schlecht: Props in State kopieren (wird nie aktualisiert)
const [name, setName] = useState(props.name)

// gut: Wert direkt verwenden, oder Komponente per key zurücksetzen
<Profile key={user.id} user={user} />
```

- Effects sind für die Synchronisation mit **externen Systemen** (DOM-API, Timer, WebSocket), nicht um State A in State B zu kopieren
- Auf Benutzeraktionen im Event-Handler reagieren, nicht per Effect

# 7.20 Hooks und moderne React Patterns / Instabile Dependencies und Stale Closures

```typescript
// schlecht: Objekt wird bei jedem Render neu erzeugt, Effect läuft immer
const options = { page, size }
useEffect(() => { load(options) }, [options])

// gut: primitive Werte als Dependency
useEffect(() => { load({ page, size }) }, [page, size])
```

```typescript
// schlecht: stale closure, count bleibt im Intervall immer 0
useEffect(() => {
    const id = setInterval(() => setCount(count + 1), 1000)
    return () => clearInterval(id)
}, [])

// gut: funktionales Update
useEffect(() => {
    const id = setInterval(() => setCount(c => c + 1), 1000)
    return () => clearInterval(id)
}, [])
```

- `useMemo`/`useCallback` nur einsetzen, wenn die Identität wirklich benötigt wird (siehe 7.11)
