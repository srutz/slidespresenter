# 14.2 Build, Deployment und Produktion / Vite Build und Environment Variables

## import.meta.env

- Vite ersetzt `import.meta.env.*` beim Build durch feste Werte.
- Eingebaute Variablen: `MODE`, `BASE_URL`, `PROD`, `DEV`, `SSR`.
- Eigene Variablen müssen mit `VITE_` beginnen, sonst werden sie nicht ins Client-Bundle übernommen.

```typescript
const apiUrl = import.meta.env.VITE_API_URL

if (import.meta.env.DEV) {
  console.log('Development mode, API:', apiUrl)
}
```

```bash
# .env
VITE_API_URL=http://localhost:3000/api
VITE_APP_TITLE=Seminar App
```

# 14.2 Build, Deployment und Produktion / .env-Dateien und Modes

- Vite lädt Dateien nach Mode; spezifischere überschreiben allgemeinere:

```bash
.env                 # immer geladen
.env.local           # immer, nicht in Git (in .gitignore)
.env.production      # nur bei vite build (mode production)
.env.staging         # nur mit --mode staging
```

```bash
vite build                  # mode production
vite build --mode staging   # lädt .env.staging, import.meta.env.MODE === 'staging'
```

- Variablen werden zur Build-Zeit eingebrannt: für eine andere Umgebung muss neu gebaut werden.
- Soll ein Image in mehreren Umgebungen laufen, bietet sich eine zur Laufzeit geladene `config.json` oder ein Reverse-Proxy mit relativer URL `/api` an.

# 14.2 Build, Deployment und Produktion / Typisierung und Sicherheit

- Typen für eigene Variablen in `src/vite-env.d.ts`:

```typescript
/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_API_URL: string
  readonly VITE_APP_TITLE: string
}

interface ImportMeta {
  readonly env: ImportMetaEnv
}
```

- Alles mit `VITE_` ist im ausgelieferten JavaScript für jeden lesbar.
- Keine Secrets im Frontend: keine API-Keys mit Schreibrechten, keine Passwörter, keine privaten Tokens.
- Geheimnisse gehören ins Backend; das Frontend ruft nur das eigene Backend auf.
- Variablen ohne `VITE_`-Präfix (z.B. `DB_PASSWORD`) werden von Vite bewusst nicht exponiert.
