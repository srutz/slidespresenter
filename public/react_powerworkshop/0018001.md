
# 18.1 React und Authentifizierung (Zusatzthema) / Authentifizierung in einer "Single Page Application" (SPA)

## Authentifizierung

- Authentifizierung ist ein wichtiger Bestandteil einer Webanwendung.
- In einer Single Page Application (SPA) wird die Authentifizierung meistens über einen Token gelöst.
- Dieser Token wird in der Regel im Local Storage oder im Session Storage gespeichert.
- Noch besser ist es, den Token im Cookie zu speichern, da dieser nicht so einfach manipuliert werden kann.

## Authentifizierung mit JWT

- JWT steht für JSON Web Token.
- Ein JWT besteht aus drei Teilen: Header, Payload und Signature.
- Der Header enthält den Typ des Tokens und den verwendeten Algorithmus.
- Der Payload enthält die Daten, die im Token gespeichert werden sollen.
- Die Signature wird aus dem Header, dem Payload und einem geheimen Schlüssel generiert.

## Authentifizierung mit OAuth

- OAuth ist ein Protokoll, das die Autorisierung von Anwendungen in einer sicheren und standardisierten Weise ermöglicht.
- OAuth ermöglicht es einer Anwendung, auf Ressourcen zuzugreifen, ohne dass der Benutzer seine Anmeldeinformationen preisgeben muss.
- OAuth verwendet Tokens, um die Autorisierung zu verwalten.

## Authentifizierung mit OpenID Connect

- OpenID Connect ist eine Authentifizierungsschicht, die auf OAuth 2.0 basiert.
- OpenID Connect fügt eine Authentifizierungsschicht hinzu, die es ermöglicht, Benutzer zu authentifizieren.

## Authentifizierung in React

- In React kann die Authentifizierung über Context-APIs oder Hooks gelöst werden.
- Die Authentifizierung wird meistens in einem separaten Modul gekapselt.
- Die Authentifizierung kann auch über Higher-Order Components oder Render-Props gelöst werden.
- Es gibt auch Libraries wie `react-auth0-spa` oder `react-keycloak` die die Authentifizierung vereinfachen.

## Authentifizierung in der Infrastruktur-Schicht

- Falls möglich sollte die Authentifizierung in der Infrastruktur-Schicht gelöst werden.
- Hierzu kann ein Load-Balancer oder ein API-Gateway verwendet werden. Dieser kann die Authentifizierung übernehmen und den Token an die Anwendung weiterreichen. Der Token wird dann vom Load-Balancer oder API-Gateway überprüft.
- Dies hat den Vorteil, dass die Anwendung selbst sich nicht um die Authentifizierung kümmern muss.

# 18.1 React und Authentifizierung (Zusatzthema) / Authentifizierung in einer "Single Page Application" (SPA)

## Authentifizierung in der Anwendungsschicht

- Falls die Authentifizierung in der Anwendungsschicht gelöst werden muss, sollte darauf geachtet werden, dass der Token möglichst sicher gespeichert wird.
- Außerdem sollte die Gültigkeit des Tokens möglichst kurz gehalten werden.
- Refresh Tokens können verwendet werden, um die Gültigkeit des Tokens zu verlängern, aber auch hier sollte darauf geachtet werden, dass diese sicher gespeichert werden und eine möglichst kurze Gültigkeit haben.
