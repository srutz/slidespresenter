# 15.7 Best Practices und Architektur / Accessibility

## Grundregeln

- Semantisches HTML zuerst: `button`, `a`, `nav`, `main`, `ul`, `h1` bis `h6` statt `div` mit `onClick`.
- Jedes Formularfeld hat ein `label` (`htmlFor` / `id`); Platzhalter ersetzen kein Label.
- Alles muss per Tastatur bedienbar sein: Tab-Reihenfolge, sichtbarer Fokus (Tailwind: `focus-visible:ring`), Escape schließt Dialoge.
- ARIA nur, wenn HTML nicht reicht: "Kein ARIA ist besser als schlechtes ARIA".
- Bilder bekommen `alt`; dekorative Bilder `alt=""`.
- Farbkontraste einhalten (WCAG AA: 4,5 zu 1 für normalen Text); Information nie nur über Farbe vermitteln.

# 15.7 Best Practices und Architektur / Fokus und dynamische Inhalte

- Beim Öffnen eines Dialogs Fokus hineinsetzen, beim Schließen zum auslösenden Element zurückgeben; das native `<dialog>` übernimmt viel davon.
- Bei Routenwechsel in der SPA Fokus auf die neue Überschrift setzen oder die Änderung ansagen.
- Statusmeldungen (gespeichert, Fehler) in `role="status"` oder `role="alert"` rendern.

```typescript
function SearchField() {
    return (
        <div>
            <label htmlFor="q" className="block">Suche</label>
            <input id="q" type="search" className="border focus-visible:ring-2" />
            <p role="status">{count} Treffer</p>
        </div>
    )
}
```

# 15.7 Best Practices und Architektur / Werkzeuge und Tests

- `eslint-plugin-jsx-a11y` im Linter aktivieren: findet fehlende Labels, ungültige ARIA-Attribute, Klick-Handler auf `div`.
- Mit `getByRole` und `getByLabelText` in React Testing Library (Kapitel 13) testen: gelingt die Abfrage, ist das Element für Hilfstechnik auffindbar.
- Mit Playwright zusätzlich `@axe-core/playwright` für automatische Prüfungen einsetzen.
- Manuell testen: nur mit Tastatur bedienen, Screenreader-Stichprobe, Browser auf 200 % zoomen.
- Automatische Werkzeuge finden nur einen Teil der Probleme.

```typescript
screen.getByRole('button', { name: /speichern/i })
screen.getByLabelText('Suche')
```
